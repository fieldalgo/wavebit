# 19. 좋은 결과인지 판단하기: 에너지 보존만으로는 부족하다

:::{note}
다운로드 가능한 교육 스크립트는 현재 물리 Problem/Job API를 사용합니다. 일부 설명 코드와 그림에는 이전 API 표기가 남아 있으므로 [현재 시작 안내](../../getting-started/index.md)와 [API 이행 안내](../../migration/index.md)를 함께 참고하세요. 과거 측정 파일과 원본 출처는 보존하며, 이전한 스크립트의 검증과 구분합니다.
:::

먼저 정의한 물리가 맞는지 확인하고, 그 다음 수치 해가 안정되는지 봅니다. 굴절률을 유전율 자리에 잘못 넣었거나 입사 방향을 반대로 생각해도 에너지 보존은 맞을 수 있습니다. 그러므로 ‘R+T=1’과 ‘내가 원한 장면의 정확한 답’은 같은 문장이 아닙니다.

이번 교재에서는 첫 격자를 **TM** 입사와 integrated/Li로 바꾸고 x 차수만 늘려보았습니다. {download}`07_convergence.py <../../../examples/rcwa/learning/learn/07_convergence.py>`의 실제 실행값입니다. 첫 TE 예제와 설정이 다르므로 같은 결과로 혼합해 비교하지 않습니다.

| Nx (Ny=0) | R | T | 에너지 잔차 abs(R+T−1) |
| --- | --- | --- | --- |
| 1 | 0.103391197 | 0.896608803 | 2.22e-16 |
| 3 | 0.256502718 | 0.743497282 | 4.00e-15 |
| 5 | 0.274911347 | 0.725088653 | 2.22e-16 |
| 7 | 0.279032278 | 0.720967722 | 1.55e-15 |
| 11 | 0.281219473 | 0.718780527 | 1.31e-14 |

모든 행의 에너지 오차는 작지만 R은 크게 변합니다. `Nx=7→11`에서도 R의 변화가 남습니다. 따라서 이 표는 수렴 완료를 선언하는 것이 아니라 **보존과 수렴을 구별하는 예시**입니다. 실제 설계는 원하는 허용 오차를 먼저 정하고, 여러 단계의 차수·표본·경계 근사 변화에서 관심량이 안정되는지 확인합니다.

위 표는 입사 매질과 유한 층이 무손실인 경우입니다. 손실 입사에서는 `R+T` 대신 `power_entering`과 투과·흡수의 관계를 사용합니다. 전력 수지의 정의는 [13장](power-and-efficiency.md)을 참고합니다.

## 무엇을 순서대로 확인할까

1. **장면**: 단위, ε와 n, 좌표 원점, 층 순서, 겹침 순서, 편광을 확인합니다.
2. **기본 물리**: 가능한 조건에서 에너지 균형, 단순 박막 극한, 대칭 등을 확인합니다.
3. **관심 출력**: 전체 R/T뿐 아니라 목표 차수, 위상, 필요한 장·기울기의 변화를 봅니다.
4. **독립된 해상도**: Fourier 차수, 재료 래스터, 도형 NVF 격자, z 분할을 구별해 바꿉니다.
5. **외부 기준**: 사용할 수 있다면 분석해나 독립 구현과 규약을 맞춰 비교합니다.

서로 가까운 두 차수의 값이 우연히 비슷할 수도 있고 공진점에서는 작은 변화가 큰 차이를 만들 수 있습니다. 다른 관측량·주변 파장까지 살펴보면 이런 문제를 찾기 쉽습니다. 기울기를 쓸 때에는 목적함수 수렴과 기울기 수렴을 따로 확인합니다.

| 증상 | 먼저 볼 곳 |
| --- | --- |
| 투과가 예상과 크게 다름 | 재료가 n인지 ε인지, 전체 T인지 T00인지 |
| 차수를 올리면 시간·메모리가 급증 | 두 방향의 곱 H, field 상태 저장, shape NVF 표본 수 |
| 장 그림만 더 매끈해짐 | 출력 표본 증가인지 Fourier 해의 개선인지 |
| 편광 변환이 뒤집혀 보임 | 입사 s/p와 출력 s/p, 각 차수의 기저와 시간 규약 |
| JIT에서 형상을 바꾼 뒤 이상함 | 오래된 StaticGeometry, trace 밖의 갱신 여부 |
| 경고나 비정상값 | 원인을 읽고 입력·정밀도·Rayleigh 근처 조건 확인 |

Rayleigh 점은 회절 차수가 전파와 감쇠의 경계에 놓이는 조건입니다. 가까운 곳에서는 분기·정밀도 처리가 중요합니다. `RayleighPointWarning`, `AutoDetuneWarning`, `PrecisionLossWarning`, `UnresolvedBranchWarning`, `GainCutoffWarning`을 무조건 지우지 말고, 실제로 어떤 처리가 일어났는지 기록합니다. `GainCutoffWarning`은 이득 반공간에서 어떤 차수가 스치는 각도(grazing) 가까이 있을 때 그 반공간마다 뜨고, 어느 차수인지는 `solver.gain_cutoff_band()`로 확인합니다. R + T가 1을 넘는다는 것만으로는 경고하지 않습니다. 이득 매질에서는 그것이 맞는 답일 수 있기 때문입니다. 숫자 하나를 억지로 얻는 것보다 조건을 명확히 하는 것이 재현에 도움이 됩니다.
