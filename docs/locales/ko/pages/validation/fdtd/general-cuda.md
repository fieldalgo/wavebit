일반 `wavebit.fdtd` API는 제한된 Torch CUDA 배정밀도 실행을 허용합니다.
계획 수립은 호스트에서 수행하고 기존 물리적 입력 검사를 유지하며, 시간
진행과 미분 가능한 관측은 CUDA에서 실행합니다. 일반 장면·관측 로컬
초기 검증 35사례는 CPU에서 가능한 입력 검사와 실제 CUDA 실행을
포함합니다. 모든 일반 FDTD 기능이나 연속체 수렴을 검증한 것은 아닙니다.
아래 체크포인트 연구는 전도체 한 사례의 비용을 측정하며 일반 장면 전체의
성능을 대표하지 않습니다.

## 허용 입력

`check`, `prepare`, `run`에 `backend='torch', device='cuda:0'`를 전달합니다.
prepared 실행은 장치를 유지하며 재사용할 때마다 새 입력을 검사합니다.
입력은 CPU에 있어도 되며 미분 가능한 장치 변환은 원래 리프와의 기울기
연결을 유지합니다. 다른 비CPU 백엔드와 단정밀도는 계속 거부합니다.

| 부분 | CUDA 허용 범위 |
| --- | --- |
| 격자와 실행 길이 | 기존 균일 정육면체 격자; 고정 실행 길이; `discretisation='voxel'`; `geometry_ranges` 없음 |
| 경계와 padding | `Periodic`, `Open`, `PEC`, `PMC`; Bloch/Periodic/Open 면만 동반하는 정적 `Bloch`; 열린 면의 `PML` padding |
| 재료 | 기존 비분산 `Material`, `ConductiveMaterial`; 아래의 별도 균질 단일 극점 ADE 범위 |
| 구조 | 셀 스냅 `Slab`; 아래 별도 제한을 만족하는 내부 `Region` 하나 |
| 광원 | `PlaneWave`, 고정 중심의 전기·자기 `Dipole`(`bspline` 또는 `tent` stamp), 초기 장; Bloch 장면에서는 PlaneWave/초기 장만 허용 |
| 관측 | `Record`, `Field`, `Flux`, 최종 장 |

초기 E/H 패턴은 고정된 호스트 선언입니다. NumPy 배열, `requires_grad`가
없는 CPU 텐서, 호스트 callable을 사용합니다. CUDA 텐서 패턴과 미분 가능한
텐서 패턴은 허용하지 않습니다. `InitialField.amplitude`는 live 입력이며
CPU에서 CUDA로 변환해도 기울기가 연결됩니다. prepared 재사용에도 이 구분이
적용되며 CUDA prepared 계약은 범위 지정 기하를 제공한다고 표시하지 않습니다.

같은 callable을 재사용해도 매 run에서 호출 결과를 평가합니다. 반환한 패턴은
중첩된 성분 값까지 동일한 고정 호스트/non-carried 제한을 따라야 하며,
callable 객체의 동일성만으로 결과를 허용하지 않습니다. H callback의 원래
반환값은 `no_grad`와 inference 문맥에서도 SI 정규화 전에 검사하므로 단위
변환으로 carried 패턴이 가려지지 않습니다. `check`와 `prepare`는
이 callback을 실행하지 않습니다. Live 초기 진폭은 계속 지원하며 이 CUDA
제한은 CPU/JAX 또는 legacy 초기 패턴 미분을 바꾸지 않습니다.
전용 초기 패턴 시험은 43사례(CPU 22, CUDA 21)를 통과했으며 같은
callable의 무효 반환값 거부와 이후 유효 반환값 복구를 포함합니다.

`Dipole.current_moment`는 전기 광원의 A·m 또는 등가 자기 광원의 V·m 단위
전류 모멘트입니다. 세기 파라미터는 `current_moment`이며,
`PlaneWave.amplitude`는 V/m 단위의 전기장 진폭입니다. 전류 모멘트·phase·
delay는 live 미분 그래프를 유지합니다. Dipole 중심과 stamp는 고정값이며
바꾸려면 다시 준비해야 합니다. 위치 미분, 주기 경계를 가로지르거나 전도성
벽에 닿거나 PML 안에 있는 지지 영역은 기존 광원 검사에서 계속 거부합니다.

CUDA의 Bloch `phase`나 `k`는 정적 값이며 순방향 AD dual과 변환·배치 래퍼를
포함한 경계값의 live 미분은 이 범위 밖입니다. 미분하지 않는 일반 호스트
스칼라 텐서는 정적 선언으로 허용합니다. 값이나 phase/k 표현을 바꾸면 다시
준비해야 합니다. Bloch와
PEC/PMC 벽 또는 Dipole 광원의 조합은 계속 거부합니다. 비스듬한 PlaneWave
각도는 라디안이며 `Bloch.from_source(source, units=...)`가 펄스 중심 파장의
고정 가로 파수 벡터를 만듭니다. 전 스펙트럼에서 일정한 입사각을 뜻하지 않습니다.

`Decay`, 다른 흡수층인 `Absorber`, 범위 지정·스무딩 기하, 균질 ADE 범위 밖의 분산 장면,
대칭·불변축 경계, TFSF 광원, 회절·원거리장 관측은 이
CUDA 범위 밖입니다. 지원하지 않는 조합은 계획 수립 전에 해당 공개 필드
경로의 `cuda_scope` 이슈를 반환합니다. 입력 허용이 표본화, CFL, 재료,
padding 등 과학적 검사를 면제하지 않습니다. `check`나 `prepare` 통과는
장을 시간 진행했다는 뜻이 아닙니다.

## 정적인 내부 Region

별도로 제한한 Region 경로는 일반 `Structure(Region(...), material)` 하나,
여섯 `Periodic` 면과 외부 광원이 없는 경우를 대상으로 합니다. 각 Region
면은 실제 반올림 격자의 가장 가까운 셀 경계로 스냅합니다. 모든 축의
채워진 구간이 `0 < lo < hi < n`을 만족해야 합니다. 주기 이음새에 닿거나
한 축 전체를 차지하거나 빈 구간으로 줄어드는 형상은 범위 밖입니다.
여러 Region, Region/Slab 혼합, continuation, `Box`, smoothing과 형상 미분은
제외합니다. 기존 Slab과 CPU 경로는 각각의 계약을 유지합니다.

배경과 내부 재료 모두 스칼라 실수 비분산 `Material` 또는
`ConductiveMaterial`을 사용하며 `mu=None`은 1입니다. 기존 유한값·양수·CFL
검사는 준비와 재사용에도 적용됩니다. Region 중심·크기와 초기 공간 패턴은
정적입니다. 형상이나 패턴을 바꾸면 다시 준비해야 하며, 호환되는 스칼라
재료 값이나 실수 초기 진폭의 변경은 기존 live 입력 경로를 사용합니다.

초기 E/H 중 하나 이상은 실제 `(3,nz,ny,nx)` 모양의 유한한 실수 plain NumPy
배열이어야 하고 다른 하나는 `None`이어도 됩니다. 텐서 패턴, callable,
성분 리스트는 이 경로에서 제외합니다. 일반 `Record`와 최종 장 출력만
허용하며 고정 실행 길이·배정밀도·voxel 표본화와 기존 선택적 체크포인트
정책을 적용합니다. Open/PML, PEC/PMC, Bloch, ADE, 광원, Field/Flux,
범위 지정 기하를 포함한 Region 장면은 이 제한 범위 밖입니다. 입력 허용이
경계면 수렴이나 일반 형상 미분 검증을 뜻하지 않습니다.

### 독립 이산 Region 기준

기준해는 선언한 기하에서 점유 셀 마스크를 독립적으로 만들고 명시적인
modulo 인덱스의 전방·후방 Yee 차분을 사용합니다. `h=Z0*H`,
`r=sigma*dt/(2*epsilon0)`, `q=(epsilon-r)/(epsilon+r)`,
`g=c0*dt/(epsilon+r)`로 두면 `h_new=h-c0*dt/mu*curl_plus(E)` 뒤에
`E_new=q*E+g*curl_minus(h_new)`를 갱신합니다. 내부 epsilon·mu·conductivity와
초기 진폭의 tangent는 전도도 분모와 자기장 계수를 포함한 독립 chain rule로
진행합니다. 제품의 curl·재료 배치·계수·AD helper는 호출하지 않습니다.
명시한 이산 갱신식을 검증하며 연속체 경계면 해를 검증하는 것은 아닙니다.

기본 사례는 dx 0.05 um, 영역 크기 `(0.61,0.49,0.71)` um, 중심
`(0.1,-0.15,0.2)` um입니다. 독립 올림으로 `(nx,ny,nz)=(13,10,15)`, 실제
아래쪽 모서리 `(-0.225,-0.4,-0.175)` um를 얻습니다. Region 크기
`(0.305,0.225,0.365)` um와 중심 `(0.0375,-0.2025,0.1625)` um는 반열린
인덱스 구간 x `[2:8]`, y `[2:6]`, z `[3:10]`의 168셀을 차지합니다.
세 순환 축 배치와 동일 SI의 um/nm 선언으로 방향과 단위 변환을 검사합니다.
초기 실수 장은 성분별 Yee 위치에서 표본화하며 여섯 성분 모두 Record와
최종 장으로 관측합니다.

검사는 17·41단계이며 체크포인트 7의 나머지는 각각 3·6단계입니다.
전체 장·Record 이력은 최대값 정규화 `2e-12`, 시각은 상대 `2e-14`, 가중
장·Record 제곱 norm과 영이 아닌 네 재료·진폭 미분은 상대 `2e-12`, 절대 0을
사용합니다. `|parameter_scale*gradient|/loss > 1e-6` 조건으로 의미 없는
미분 비교를 막습니다. CUDA 검증 전에 마스크 이동, floor/nearest 차이,
축·주기 연결·curl 부호 오류, mu 누락, 전도도 분모·tangent 항 누락을 각각
`1e-4`보다 크게 구별해야 합니다. 여덟 mutant 모두 사전 기준을 통과했으며
가장 작은 분리는 `0.0111898253`이었습니다. 두 중앙차분 간격으로 해석적
접선을 상대 `2e-6` 기준에서 독립 검사했고 최대 차이는 `1.15306194e-6`이었습니다.

내부 재료 재사용 사례는 `(epsilon,mu,sigma,A)=(2.25,1.3,600,1.2)`와
`(1.8,1.1,900,0.7)`을 사용하며 전도도 단위는 S/m입니다. CUDA 재료 리프와
CPU 진폭 리프는 같은 prepared 장면에 연결됩니다. 입력 패턴·리프 소유권과
이전 출력은 보존됩니다. 별도 무손실 사례는 `Material`을 검사합니다.
비진공 배경 `(epsilon,mu,sigma)=(1.4,1.1,80)`은 회전 1·41단계에서 각각
새 um/nm 실행으로 배경 재료·진폭 미분을 비교합니다. 이는 단위 쌍 검사이며
배경 재료의 prepared 재사용 검사는 아닙니다.

| 검증 | 호스트 사례 | 실제 CUDA 사례 |
| --- | ---: | ---: |
| 독립 마스크/Yee/접선, 장, Record, 재사용과 단위 | 25 | 17 |
| 입력 허용·변환·거부 및 같은 리프의 invalid/recovery 계약 | 51 | 6 |
| 고유 신규 사례 | 76 | 23 |

**고유 신규 99사례가 모두 통과**했습니다. 호스트 76사례는 장치 없이
실행한 검사 44개와 실제 CPU 실행 32개입니다. CUDA 23사례는 10.40초에
통과했고 경고 25개가 발생했습니다. 반복 검증은 고유 사례 수에 더하지
않았으며, 기존 CPU 회귀 검사 25개도 별도로 통과했습니다.

기록된 내부 재료 재사용 장·Record 오차의 최대값은 `3.97962361e-15`입니다.
기록된 내부·배경 목적함수 기울기를 독립 감사한 최대 상대 오차는
`9.28604067e-14`로, 기존 `2e-12` 기준을 만족합니다. 무손실·단위 쌍의 장
assertion도 통과했지만 개별 오차를 기록하지 않았으므로 내부 재사용의
최대값을 모든 장 사례의 최대값으로 해석하지 않습니다. 이 결과는 제한된
이산 1차 미분 계약을 검증하며 연속체 경계면 정확도·형상 미분·임의 Region
조합을 검증하지 않습니다.

## 유한한 광원 값과 prepared 복구

광원 진폭·phase·delay와 `InitialField.amplitude`는 유한해야 합니다.
광원의 `Band.wavelength`와 `Band.df`는 양수이면서 유한해야 합니다.
복소 진폭은 기존 장 계약에서 허용하는 경우에만 실수부·허수부를 모두
검사하며, 실수 실행의 복소 진폭은 계속 거부합니다. Dipole의 공개 세기
파라미터는 `current_moment`이며 lowering이 여기서 광원 진폭을 유도합니다.

이전에는 live 광원 또는 초기 진폭 리프를 NaN으로 바꾸면 장이 NaN이면서
`result.validity.checks['runtime_stability']`가 true로 남을 수 있었습니다.
이제 광원 입력 범위 검사를 기존 런타임 유효성 계수에 합칩니다. 읽을 수
있는 잘못된 선언은 기존 생성자가 먼저 거부할 수 있고, 그렇지 않으면
잘못된 광원 리프가 실패한 런타임 유효성과 NaN 장을 반환하게 합니다.
최적화처럼 같은 리프 값을 제자리에서 갱신하는 것 자체가 prepared 구조를
비호환으로 만들지는 않습니다. 유효한 리프 값으로 복원하면 같은 준비를
다시 실행할 수 있으며, 이전에 반환한 결과는 변하지 않아야 합니다.

유효한 concrete 광원 값은 들어온 안정성 계수를 바꾸지 않습니다. 초기
패턴·광원·복소 장의 허용 범위를 넓히지 않습니다. 위 입력 값의 범위를
검사하는 것이며 유도한 파형 연산의 모든 오버플로를 검사하지는 않습니다.
아래의 별도 live Band cutoff guard는 스펙트럼 부등식을, 후속 pole-free
resolution guard는 별도의 공간 certificate를 추가합니다. 수치·미분 검증 범위는
실제로 실행한 사례로 한정합니다.

`test_general_source_finite.py`의 **새 77사례**가 통과했습니다. CPU 44사례와
실제 CUDA 33사례입니다. 공개 valid→invalid→valid 실행은 같은 광원 진폭·
phase·초기 진폭 리프를 제자리에서 갱신하며, 리프의 동일성과 이전 출력을
보존하고 원래 장과 광원 이력을 정확히 복구합니다. 직접 guard 검사는 NaN,
양·음의 무한대, 양수가 아닌 파장·대역폭, 복소수 양쪽 성분, 혼합 장치
리프, 유효한 concrete guard의 동일성, Torch 논리 view와 bfloat16 변환을
포함합니다. Torch 순방향·배치 변환과 JAX JIT·미분은 helper 수준의 검사이며,
임의의 전체 solver 변환이나 복소 Dipole 허용을 검증한 것이 아닙니다.

별도로 기존 CPU CPML 진폭·phase Hessian 두 사례와 기존 CPU 광원 미분·
파형 세 사례가 해당 Torch/JAX 및 Dipole/TFSF/PlaneWave 경로에서 통과했습니다.
기존 실제 CUDA 열 사례도 통과했습니다. CPML Hessian 네 사례, 복소 Bloch
관측 Hessian 두 사례, 정확한 전도체 Hessian 두 사례와 전도도·초기 진폭
미분 두 사례입니다. 기존 수치 기준을 그대로 유지했고 CUDA 실행의 격자·
관측창 경고 46개도 남겼습니다. 이 결과는 제한된 회귀 검사이며 전체 CI나
최적화 수렴 검증은 아닙니다.

### Live Band carrier cutoff

미분·변환 값을 담은 파장 또는 대역폭도 concrete 생성자의 엄격한 양의
스펙트럼 하한 조건을 유지합니다. 물리 SI 단위로는
`f0=c0/wavelength > k*frequency_sigma_hz`, `k=sqrt(-2*log(cutoff))`입니다.
엔진의 정규화 Band 단위에서는 `f0=1/band.wavelength`와 `k*band.df`를
검사합니다. 두 유도량 모두 유한해야 하며 cutoff에서의 등호는 실패합니다.
기존 리프의 유한한 양수 검사도 계속 적용됩니다.

이전에는 같은 live 파장·대역폭 리프를 주파수 0에 닿는 스펙트럼으로 바꾸면
concrete 입력은 거부되는데도 유한한 장과 `runtime_stability=True`를 반환할
수 있었습니다. 수정 전 CPU 1개와 실제 CUDA 2개에서 재현했습니다. 이제
backend predicate가 잘못된 carried band의 장을 NaN으로 만들고 런타임
유효성을 실패시킵니다. 같은 리프를 유효한 값으로 복원하면 과거 결과·리프
소유권·기존 `.grad` 버퍼를 바꾸지 않고 원래 출력을 복구합니다.

순방향·배치 Torch와 JAX 미분 값을 포함해, 두 스펙트럼 리프를 host에서
읽기 전에 carried-band 분기를 선택합니다. 이 분기는 유효성 certificate만
추가하며 실제 파형 lowering은 물리 리프와 미분을 유지합니다. 일반 concrete
Band 처리는 유효한 입력의 기존 guard 동일성을 포함해 변하지 않습니다.
phase만 carried인 경우 concrete band를 다시 검사하지 않습니다. 새 광원·
재료·기하·변환 입력 허용을 추가하지 않습니다.

`test_general_source_band_guard.py`의 **새 43사례: CPU 22개·CUDA 21개가
통과**했습니다. 공개 복구 사례는 주기적 8³·17단계 Ey Dipole에서 같은
파장·대역폭 리프를 사용하며 CUDA plain과 체크포인트 7을 검사합니다.
helper 사례는 엄격한 경계값, 파장만 또는 대역폭만 carried인 경우, 혼합
리프 장치, 두 스펙트럼 유도량의 오버플로, 이전 실패 유효성 보존, Torch/JAX
미분·배치 certificate를 검사합니다. Helper 변환이 임의의 공개 solver 변환
지원을 뜻하지 않습니다.

**관련 98사례도 모두 통과**했습니다. CPU는 유한 excitation 44개·기존 광원
검사 3개·펄스 Hessian 9개이며, CUDA는 유한 excitation 33개·펄스 Hessian
9개입니다. 관련 CUDA 42개는 28.07초·경고 10개로 통과했습니다. 신규 43개와
합쳐 고유 로컬 141사례이며 전체 CI나 FDTD GPU 전체 검증 완료를 뜻하지
않습니다. 모든 수치·미분 허용오차는 그대로 유지했습니다. 주 CUDA 펄스
검사 8개의 모든 기록 property 문자열이 guard 전 검증과 정확히 같아 기존
순방향·목적값·기울기·Hessian 최대 오차도 유지됩니다. 아홉 번째 단위 쌍은
계속 assertion 근거만 제공합니다. 실행 중 소스 사본과 전후 해시는 변하지
않았습니다.

Carrier guard만으로 공간 해상도나 모든 파형 중간 연산의 범위를 보장하지
않습니다. 아래의 후속 pole-free certificate는 현재 값에서 기존 공간 하한을
검사합니다. 어느 guard도 최적화의 전체 파라미터 범위나 연속체 정확도를
보증하지 않습니다.

### Live Band pole-free spatial resolution

파장 또는 대역폭이 미분 값을 담고 **선언된 모든 재료에 극점이 없으면**,
backend certificate가 실행마다 기존 광원·보고서의 공간 하한을 검사합니다.
정규화 Band 단위에서
`lambda_min = min_sources(1 / (1/lambda + k*df))`를 계산하며 concrete인 다른
광원도 포함합니다. Concrete 재료를 포함한 배경과 모든 구조를 검사하고,
최단 파장은 유한한 양수여야 합니다. 기존 굴절률 규칙은
`abs(epsilon*mu)`가 가장 큰 성분(동률이면 첫 성분)의 수동 제곱근을
선택합니다. 파동 규칙은 **매질 내 파장당 8셀**에서 등호를 허용합니다.
기존 금속 광원·보고서의 skin-depth 규칙과 정적 Diffraction 파장의 파동
규칙은 구분해서 유지합니다. 전도도는 기존 conductive-film descriptor가
성립할 때만 이 certificate에 들어가며, 일반 전도도 해상도 규칙이나 필름
허용 범위를 추가하지 않습니다.

Certificate만 detach하며 실제 광원·재료 리프와 파형 미분은 유지합니다.
모두 concrete인 Band 처리는 변하지 않습니다. **선언된 재료 하나라도
극점이 있으면**, 세기가 0인 비활성 극점을 포함해 기존 live-material 검사
등 이전 해상도 경로 전체를 유지합니다. 그 장면의 동적 Band 해상도를 새로
보증하지 않습니다. 광원·매질·기하·관측·변환 허용 범위를 넓히지 않습니다.
Host의 `CoarseMeshWarning`은 계획 단계에서 traced 최단 파장을 읽지 못했다고
계속 알릴 수 있습니다. 이 host 보고서 한계와 제한된 런타임 certificate는
별개이며, 경고가 측정된 거친 격자 오차를 뜻하지 않습니다. 8셀 하한은
거부 기준이지 정확도나 수렴 보증이 아닙니다.

원래 파장 갱신은 concrete 입력이 거부되는 하한 미만에서도 유한한 장과
성공한 런타임 유효성을 반환했으며 CPU 1개·CUDA 2개에서 재현했습니다.
별도의 대역폭만 바꾸는 갱신은 파장을 고정한 채 약 9.01셀에서
`7.3330730`셀로, 파장 갱신은 `7.55748757`셀로 이동합니다. 두 경우 모두
양의 carrier cutoff를 유지합니다. 수정 후 공개 valid→invalid→valid 검사는
잘못된 점에서 NaN 장과 실패한 런타임 유효성을 반환하고, 이전 결과와
리프·`.grad` 소유권을 보존하며 정확히 복구합니다. 주기적 8³·17단계 Ey
Dipole에서 CPU plain과 CUDA plain·체크포인트 7을 사용합니다.

`test_general_source_resolution_guard.py`의 **새 30사례: CPU 25개·CUDA
5개가 통과**했습니다. Helper 대조군은 등호를 포함한 하한과 인접 부동소수점
값, 모든 광원·재료 선택, 이전 실패 유효성, 정적 Diffraction, descriptor로
한정한 전도도, 극점이 있을 때 전체 이전 경로 유지, live band의 host 읽기
없이 상수인 Torch/JAX 미분 certificate를 검사합니다. 이는 일반 solver
변환 지원을 뜻하지 않습니다. 첫 CPU 묶음 119개가 통과한 뒤 추가한 대역폭
갱신 CPU 1개만 별도로 통과했습니다. **관련 125사례**는 CPU 재료 해상도
64개, carrier cutoff CPU 22개·CUDA 21개, 펄스 CPU 9개·CUDA 9개입니다.
새 검사와 관련 검사를 합쳐 **고유 로컬 155사례**이며 전체 CI는 아닙니다.
새 CUDA 5개는 2.64초·경고 9개, 관련 CUDA 30개는 27.49초·경고 13개로
통과했습니다.

소스 사본과 전후 해시는 변하지 않았습니다. 주 CUDA 펄스 8개의 모든 기록
property 문자열이 원래 펄스 검증과 정확히 같아 보고한 순방향·목적값·
기울기·Hessian 최대 오차를 유지합니다. 아홉 번째 단위 쌍은 assertion
근거만 제공합니다. 수치 허용오차도 그대로입니다. 극점을 선언한 장면과
다른 파형 중간 연산의 오버플로는 추가 certificate 범위 밖이며 독립적인
물리 해상도 세분화는 여전히 필요합니다.

## Fixed-time waveform representability

유한한 광원 입력만으로 표본화한 Gaussian 파형의 표현 가능성을 보장할 수는
없습니다. 원래 회귀 사례에서 정규화한 delay를 유한한 값 `1e308`로 바꾸면
표본 drive가 비유한 값이 되고 전기장이 NaN이지만 `runtime_stability`는
true로 남았습니다. CPU 한 사례와 CUDA 두 사례(plain, checkpoint-7)가
이 공백을 재현했습니다. 원래 delay를 복원하면 같은 준비를 재사용할 수
있었고, 이전에 소유권을 분리해 반환한 결과도 변하지 않았습니다.

제한적 guard는 고정 시간 광원 연산을 확인합니다. Lowering한
`tau`, `f0`, `t0`가 양수이면서 유한한지, 각 광원 표본 행의 양 끝에서 이동한
시간·정규화한 시간·그 제곱·Gaussian 지수 `-0.5*(s/tau)**2`·carrier
prefactor `omega=2*pi*f0`·phase `omega*s+phase`가 유한한지 검사합니다.
실제 광원 행마다 `n=0`, `n=steps-1`을 사용하며 row shift는 전기 0.5,
자기 0, column 1을 유지합니다. 커널의 연산 순서를 바꾸지 않습니다.
양수인 고정 시간 간격에서는 끝점 경계로
중간 표본의 유한성을 확인하므로 매 단계 검사나 전체 장 스캔은 필요하지
않습니다. 두 경로 모두 NumPy로 연산을 재구성하지 않고 실제 lowering된
backend 파라미터로 predicate를 계산합니다. 완전한 eager concrete 실행은
광원마다 run당 backend boolean 하나를 읽습니다. 무효 선언은
`source_waveform_range` 코드의 `ValidationError`를 발생시키고, 유효 선언은
들어온 guard의 동일성을 유지합니다. CUDA에서는 광원마다 run당 한 번의
스칼라 동기화가 필요하며, 시간 단계마다 동기화하는 것은 아닙니다.
원래 입력·lowering된 파라미터·predicate 중 하나라도 미분 또는 변환 trace를
가지면 host에서 읽지 않고 상수 1 또는 NaN 인자를 기존 런타임 certificate에
합칩니다. 따라서 JIT에서 유도된 상수도 traced 인자 1을 사용할 수 있으며
guard가 문자 그대로 `None`인 동일성까지 보장하지 않습니다. Carried 경로의
시간 측정은 concrete 스칼라 동기화 비용을 측정한 것이 아닙니다.
`test_general_source_waveform_guard.py`는 **새 36사례(CPU 19, CUDA 17)**를
통과했습니다. CPU는 5.24초·경고 4건, CUDA는 2.97초·coarse-mesh 경고
6건과 Torch JIT future warning 1건입니다. 양수·음수의 매우 큰 delay는
이제 런타임 유효성을 실패시키고 NaN 장을 전달합니다. 같은 잎을 복원하면
정확히 회복하며 이전 출력·잎의 동일성·기존 `.grad` 버퍼는 변하지 않습니다.
Concrete 무효 값은 구조화된 거부를 받습니다. 개별 중간 연산 오버플로,
마지막 표본, 전기·자기 row shift, backend `t0` 오버플로 경계의 인접값,
유효 guard 동일성과 변경하지 않은 source-free·`Decay` 경로도 검사했습니다.
Torch forward/reverse/batch와 JAX JIT/gradient/Hessian/batch 검사는 상수
certificate에 한정되며 임의 변환을 적용한 전체 solver를 검증한 것은 아닙니다.

관련 다섯 시험 파일은 **174사례**를 78.26초·경고 44건으로 통과했습니다.
유한 여기 77, carrier cutoff 43, 공간 해상도 30, 펄스 고차 미분 18,
projected pulse fitting 6사례입니다. 새 36사례와 합쳐 이번 변경의 검증은
**중복 없는 210사례**이며 앞선 일부 재실행을 더하지 않았습니다. 보존한
소스 사본과 현재 소스 해시도 일치했습니다. 제한된 로컬 검증이며 전체 CI는
아닙니다.

이는 Gaussian 식을 바꾸는 것이 아니라 표현 가능 범위를 제한하는 검사입니다.
이상적인 envelope가 0이더라도 매우 큰 유한 펄스 선언은 거부될 수 있습니다.
파형 연산·광원 및 장의 허용 범위를 바꾸거나 적응형 `Decay` 경로를 검증하지
않습니다. `runtime_stability`가 true라는 것은 구현된 certificate를
통과했다는 뜻이며, 모든 출력·중간값·미분값이 유한한지 전부 검사했다는 뜻은
아닙니다.


제한적 비용 비교는 같은 8³ bspline 펄스, plain scan, 17·41단계에서 warmup
한 번 뒤 `torch.no_grad()` 아래 공개 `prepared.run`을 다섯 번 호출했습니다.
Preparation과 계측기의 수치 검사는 시간 밖에, 공개 validation·lowering·adaptation은
시간 안에 두었으며 CUDA는 시간 경계에서 동기화했습니다. CPU는 한 스레드입니다.
변경 전 소스는 `76bdea9b`이며 guard 구현만 달라졌습니다. Concrete baseline의

## 같은 리프의 SGD 재사용

`studies/fdtd/general_cuda/optimizer_reuse.py`는 같은 학습 리프를 반복해서
갱신하며 prepared 실행을 재사용하는지 검사합니다. 전기 Ey Dipole 사례는
축마다 물리 셀 12개, 각 Open 면에 PML 셀 네 개를 더한 실제 20³ 격자에서
41단계를 실행합니다. 일반 스캔과 체크포인트 7은 같은 물리를 사용하며
체크포인트 끝에는 여섯 단계가 남습니다. 짧고 얇은 PML을 쓴 이 사례는
이산 미분·수명주기 연구이며 PML 정확도나 성능 벤치마크가 아닙니다.

광원 위상 0과 pi/2의 NumPy 실행 두 개에서 최종 장 기저 `b0`, `b1`을
얻습니다. 각 벡터는 일관된 SI 장 단위의 E와 Z0 H를 이어 붙입니다.
`S = ||b0||² + ||b1||²`, `G_ij = dot(b_i,b_j)/S`,
`u(phi) = (cos(phi), sin(phi))`, `r = A*u(phi) - 1.1*u(0.2)`로 두면
정규화한 fitting 손실은 `L = r.T*G*r/2`이고 미분은
`dL/dA = u.T*G*r`, `dL/dphi = A*u'.T*G*r`입니다. 이는 **같은 이산 solver**에
대한 독립적인 대수적 값·기울기·갱신 기준이며 독립 Maxwell 해가 아닙니다.
목적함수는 최종 장만 사용하고 광원 파형을 제외하며 줄 단위 에너지가 아닙니다.

각 실행은 `(A,phi)=(0.8,-0.3)` 또는 `(1.4,0.7)`에서 시작하여 학습률 0.125,
`foreach=False`, `zero_grad(set_to_none=True)`로 SGD를 16번 갱신합니다.
A는 무차원이며 광원 전류 모멘트는 `1e-16*A` A·m, 위상은 라디안입니다.
진폭 리프는 CPU에, 위상 리프는 실행 장치에 유지합니다. 리프 동일성·저장
주소·dtype·장치를 유지하고 제자리 갱신마다 버전 카운터가 증가해야 합니다.
장은 기저와 최대값 정규화 `2e-12`로 비교합니다. 손실·기울기·갱신된
파라미터는 해석적 갱신식과 상대 `2e-12`, 절대 0으로 비교하며 비교량이
영이 아닌지도 검사합니다. 첫 두
반복 동안 이전 출력을 보유하여 정확히 변하지 않았는지 검사합니다.
별도의 NaN 진폭·위상 갱신은 유효성 실패 또는 유한값을 명시한 구조화된
거부를 받아야 하며 같은 리프와 prepared 객체에서 복구해야 합니다.

CUDA에서는 이전 출력을 해제한 뒤 매 반복의 allocated 바이트가 지속해서
보유하는 목표 장·리프의 정확한 기준값으로 돌아와야 합니다. 증가 허용량이나
반복 중 캐시 비우기를 사용하지 않습니다. peak 카운터는 0부터 센 반복 1까지 누적하고
한 번 초기화한 뒤 다시 누적하므로 반복별 최대값이 아닙니다. 마지막 텐서
해제 후 allocated가 프로세스 기준값으로 돌아와야 하며 이후 캐시를 해제합니다.
reserved와 드라이버 메모리는 별도로 기록합니다. 루프 시간에는 검증·동기화·
호스트 복사·가비지 수집·기록 쓰기가 포함되므로 solver 속도 비교가 아닙니다.

새 외부 출력 디렉터리, 일치하는 소스·기저 해시와 별도 120초 제한의 CUDA
감독 프로세스를 사용합니다. CUDA 시작에는 가용 메모리 5 GiB를 요구하고
Torch 할당자는 4 GiB로 제한하지만, 메모리를 예약하거나 드라이버·다른
프로세스 사용량을 제한하지는 않습니다. 실행 전에 정확한 소스 사본과 시도
기록을 만들며 소스·기저 파일이 없거나 달라지면 해당 시도를 무효화합니다.
전체 기록 계약은 연구 디렉터리 README를 참고하세요.

### 옵티마이저 연구 결과

연구의 **대수·기록·CLI 제어 테스트 24개가 통과**했습니다. 별도로 NumPy
기저 생성 명령, CPU 일반 루프 두 실행과 실제 CUDA 네 실행(두 초기값 ×
일반/K7)이 통과했습니다. 이 여섯 실행은 CLI 연구 실행이며 추가로 실행한
pytest 여섯 사례가 아닙니다. 대응하는 통합 사례는 테스트 파일에 제공합니다.
각 루프는 16번의 갱신과 잘못된 입력 복구 두 검사를 모두 완료했습니다.
기저 Gram 행렬은 양의 정부호였고 조건수는 `73.9756791383416`이었습니다.

CPU 기울기의 최대 상대 오차는 `3.025309471976914e-15`였습니다. CUDA 네
실행의 최대 상대 손실·기울기·갱신 후 파라미터 오차는 각각
`5.096959445281874e-15`, `4.421606151350874e-15`,
`1.380285480163295e-15`로 기존 `2e-12` 기준을 만족했습니다. 이전 출력,
리프 동일성·버전, 잘못된 입력 복구 검사도 모두 통과했습니다. 이는 정해진
비선형 SGD 갱신식과의 일치를 검증하며, 수렴 임계값이나 목표 파라미터의
복원을 합격 조건으로 삼지 않았습니다.

보유하던 이전 출력을 해제한 뒤 CUDA의 매 반복은 **allocated 384512바이트**로
돌아왔습니다. 목표 장 384000바이트와 위상 리프의 512바이트 할당 블록이며,
CPU 진폭 리프는 이 장치 합계에 포함되지 않습니다. 두 초기값 모두 0부터
센 반복 1이 끝난 뒤 한 번 초기화한 peak 카운터에서 다음 값을 보였습니다.
따라서 표는 반복 2–15의 누적 최대값입니다.

| 스캔 정책 | Peak allocated 바이트 | Peak reserved 바이트 | 매 해제 후 allocated |
| --- | ---: | ---: | ---: |
| 일반 | 3315712 | 6291456 | 384512 |
| 체크포인트 7 | 7171072 | 12582912 | 384512 |

이 작은 사례에서는 체크포인트의 allocated와 reserved가 더 컸습니다.
보편적인 체크포인트 순위나 총메모리 상한을 뜻하지 않습니다. 반복 중에는
캐시를 비우지 않았습니다. 마지막 텐서 정리 뒤 allocated는 프로세스 기준값
0으로 돌아왔지만 reserved는 명시적으로 캐시를 해제하기 전까지
6291456/12582912바이트로 남았습니다. 캐시 해제 후 allocated/reserved는 모두
0이었고 드라이버 가용 메모리는 7389315072바이트였습니다. 이 할당자 검사가
CUDA 드라이버·컨텍스트 할당까지 0이라는 뜻은 아닙니다.

검사가 포함된 루프 총시간은 초기값 0/1에 대해 일반 스캔 9.2828/9.1116초,
K7 13.2623/13.0117초였습니다. 위의 검사·기록 작업을 모두 포함하므로 성능
비교 수치가 아닙니다. 각 실행에서 소스 파일 263개의 해시와 기준 기록·기저
파일 해시가 유지되었습니다. 환경은 Python 3.12.14, Torch 2.14.1+cu130,
CUDA 13.0, NumPy 2.5.4, Windows 11, RTX 4060 Ti, Torch CPU 스레드 하나입니다.
이 제한된 로컬 결과는 검토 대상 CI를 대신하거나 임의의 최적화 알고리즘·
목적함수·긴 궤적·재료 최적화·다른 장치를 검증하지 않습니다.

아래 명령은 초기값 0을 보여 줍니다. CPU, CUDA 일반, CUDA K7을 각각
`--seed 1`과 서로 다른 새 출력 디렉터리로 반복하면 두 초기값을 재현합니다.
기본 `--block 0`은 일반 스캔을 선택하며 공개
`Numerics(checkpoint_steps=0)`을 뜻하지 않습니다.

## 균질 단일 극점 ADE

제한된 분산 경로는 실제 격자 전체를 덮는 `Slab` 하나에
`DispersiveMaterial`을 놓고, 여섯 면 모두 `Periodic`이며 `Lorentz` 또는
`Drude` 극점이 정확히 하나인 경우입니다. 기존 균일 격자·고정 실행 길이·
배정밀도·voxel 조건을 유지합니다. 재료 경계면이나 외부 광원은 없고 배경
선언은 일반 `Material`입니다. 초기 E/H는 전체 격자의 `(3,nz,ny,nx)` 모양인
유한 실수 NumPy 배열이며, 하나는 `None`으로 두어 영인 장을 사용할 수
있습니다. 이 ADE 범위는 CPU 텐서·callable·성분별 리스트를 허용하지
않습니다. 실수·정수 배열은 배정밀도 실행 값으로 변환하고 float32의 기존
정밀도 경고는 유지합니다. `Record` 또는 최종 장을 관측하며,
`final_fields=False`인 Record 전용 실행도 가능합니다.
Open/PML, Bloch, 벽, 여러 극점, Debye, 분산 배경 재료, 공간 필름,
푸리에·Flux 관측은 이 경로 밖입니다.

`epsilon_inf`, `mu`, 감쇠 `gamma`, Lorentz `omega_0`는 비미분 스칼라이고
`mu=None`은 1입니다. resolved plan이 호환되고 과학적 검사를 통과하면
prepared 재사용 시 구체적인 값을 바꿀 수 있습니다. 이는 변경 시 다시
준비해야 하는 고정 공간 패턴과 다릅니다. 허용하는 미분 입력은 실수 스칼라
`InitialField.amplitude`와 기존 SI 극점 단위를 쓰는
Lorentz `strength` 또는 Drude `omega_p`입니다. 초기 공간 패턴 자체는
미분 입력이 아닙니다. 기존 재료 유효성·극점별 시간 간격 검사를 유지하며,
수동성·유한성·안정성 제한을 면제하지 않습니다.

축소 저장 경로에도 기존 스칼라 갱신식 산술 검사를 적용합니다. 양의 유한
극점 선언이라도 0 아닌 구동 계수가 표현 범위를 벗어날 수 있습니다.
구체값은 `PoleArithmeticRefused`로 거부하며, 추적되는 live 값은 결과의
`runtime_stability`를 false로 표시하고 무효 장을 전달하여 안정한 결과로
보고하지 않습니다. Lorentz·Drude 모두 정상→무효→정상 prepared 재사용을
검사합니다. 전용 산술 회귀의 CPU·장치 불필요 여덟 사례와 실제 CUDA
두 사례, 기존 혼합 산술 38검사가 통과했습니다. 산술 계약을 보존하는
검사이며 허용 재료 범위를 넓히는 것이 아닙니다.

기존 초기화는 알고리즘의 편극 메모리와 다음 단계에 전달할 편극 증가량을
0으로 둡니다. 따라서 첫 E 갱신에는 전달된 극점 증가량이 없고, 그 뒤에
극점을 진행합니다. 이는 이산 초기 상태이며 연속체의 평형 편극 초기화가
아닙니다. 균일 전기장의 고정 시간 세분화 진단에서 시험한 Lorentz·Drude
사례는 원래 시간축 기준 일차 시간 오차를 보입니다. 별도로 기준 시간을
`(n-.5)*dt`로 옮기면 초기화 위상 차이를 설명할 수 있지만, 해를 수정하거나
원래 시간축의 이차 연속체 정확도를 입증하지는 않습니다.

CPU 진단 두 사례는 격자와 물리적 종료 시간 `6.671281903963041e-15`초를
고정하고 64/128/256단계를 사용합니다. 전체 시간창의 최대 오차와 연속한
구간의 관측 차수는 다음과 같습니다.

| 극점 | `n*dt`의 원래 오차 | 원래 차수 | `(n-.5)*dt`의 이동한 오차 | 이동한 차수 |
| --- | --- | --- | --- | --- |
| Lorentz | 0.0148468 / 0.00748655 / 0.00376165 | 0.98778 / 0.99293 | 0.00234079 / 0.000592359 / 0.000149097 | 1.98245 / 1.99022 |
| Drude | 0.0357578 / 0.0179577 / 0.00900017 | 0.99366 / 0.99658 | 0.000903182 / 0.000229998 / 0.0000580323 | 1.97339 / 1.98670 |

이는 기존 초기화의 진단값이며 결과에 맞춘 수용 차수가 아닙니다.
세 시간 해상도 모두 독립 이산해 검사를 통과합니다.

독립 검사는 균일 장에 SI 특성근·스칼라 갱신식을, 0 아닌 푸리에 모드에
직접 구성한 15×15 맥스웰·편극 상태 행렬과 물리적 Yee 위치를 사용합니다.
극점 누락·잘못된 초기화 대조군은 검출 가능한 차이를 내야 합니다.
장·Record 최대값 정규화 오차 기준은 `1e-11`, 균일 갱신식 잔차는 `1e-12`
입니다. 45×45 행렬 거듭제곱의 Frechet 미분이 최종 장 및 부호를 포함한
Record 이력 목적함수의 진폭·재료 기울기와 전체 Hessian을 제공합니다.
기준은 상대 `2e-12`, 절대 0입니다. 일반·체크포인트 스캔, 서로 다른 장치의
리프, prepared 재사용과 이전 결과 보존을 별도로 검사합니다. 이 기준은
선언한 이산 초기화를 공유합니다. Eager 역방향 미분과 double backward를
검증하며 임의의 연속체 초기 상태나 일반적인 변환을 검증하지 않습니다.

공개 수치 검증은 CPU 고유 40사례(변하지 않은 통과 26사례 유지, 수정한
14사례 재실행)와 **실제 CUDA 42사례**(10.99초, 40 deselect, 예상한 격자
경고 51개)를 포함합니다. 별도의 계약 검사는 장치가 필요 없는 58사례와
CPU 7사례, 이후 실제 CUDA 6사례(0.90초, 65 deselect, 예상 경고 7개)가
통과했습니다. 새 고유 사례는 합계 153개이며 기존 범위 거부 9사례는
별도입니다. 실험용 컨텍스트 없이 공개 입력 허용 경로를 실행한 결과입니다.

진폭·재료 파라미터 두 점, CPU 진폭 리프와 실행 장치의 재료 리프를
사용합니다. Record 목적함수는 시간·공간이 엇갈린 여섯 성분 모두의 가중
제곱과 0 아닌 부호 있는 선형 항을 사용하며 최종 장 출력은 필요하지
않습니다. 계약 검사는 유효하지 않은 live 재료 처리, float32·정수 변환,
정밀도 경고와 CPU epsilon 미분 경로도 유지합니다. 기준을 완화하지
않았습니다. 이 로컬 검증은 전체 CI, 릴리스 통합, 일반 분산 CUDA 지원이나
원래 시간축의 이차 연속체 초기화를 입증하지 않습니다.

### CUDA 극점 상태 축소

위에서 허용한 균질 범위에서는 Torch CUDA 준비가 현재·이전 편극 벡터만
전달하는 극점 항을 선택합니다. 세 번째 증가량 벡터를 상태로 전달하는 대신
각 E 갱신 직전에 두 편극의 차를 한 번 계산합니다. 갱신 순서와 메모리가
0인 초기화는 유지되고, 1·2차 미분은 아래에서 독립적으로 검증합니다.
Autograd 그래프 자체는 달라집니다. 상태 저장을 바꾼 것이며 연속체
초기화를 수정하거나 재료 허용 범위를 넓힌 것이 아닙니다. 항의 형식은
plan 식별에 포함되고 호환되는 prepared 재사용에서도 다시 선택됩니다.
축소된 plan은 CPU나 Torch 외 백엔드에서 실행할 수 없습니다.

일반 CPU, NumPy/JAX 및 다른 기존 극점 사용 경로는 원래 항을 유지합니다.
특히 소스가 있는 plan, `Decay`, 필름, 소스 열, 하위 클래스, 여러 극점,
CPML, 기하 범위로 확장하지 않습니다. 배정밀도 전체 격자 극점 하나에서
논리적 E/H+극점 보고량은 스칼라 성분 15개(셀당 120바이트)에서
12개(96바이트)로 줄어듭니다. 극점 이력만 보면 성분 아홉 개에서 여섯 개로
줄어듭니다. 이 20% 논리 상태 감소가 allocated/reserved 최대값을 예측하지는
않습니다. 역전파 그래프, 체크포인트 경계, 관측, 임시 텐서의 수명은 별개입니다.

앞의 수치 표는 상태 저장 변경 전의 검증 기록입니다. 별도 32³/64³·163단계
연구 비교에서는 일반·블록 8·블록 32 모두 allocated 최대값이 줄었으나,
모든 쌍의 시간 범위가 겹쳤습니다. 이 과거 측정은 변경의 근거이며 최종 제품
경로의 측정이나 일반적인 가속의 근거가 아닙니다. 현재 제품의 재현은
`studies/fdtd/general_cuda/ade_cost.py`가 일반 공개 준비 경로를 사용하며,
런타임이나 극점 팩터리를 교체하지 않습니다. 시간 측정 밖에서 독립 특성근,
갱신식, 진폭·재료 미분을 확인하고 논리 payload, 순방향 후 보유 그래프,
측정 구간의 할당자 최대값을 구분합니다. 새 프로세스 명령, 소스 식별,
64³ 실행에 필요한 동일 조건의 32³ 예측 기록은
`studies/fdtd/general_cuda/README.md`를 참고하세요.

최종 축소 구현은 **기존 ADE 153사례**를 다시 검증했습니다. CPU·장치 불필요
105사례와 실제 CUDA 48사례이며, 앞의 근거를 재검증한 것이지 새 153사례가
추가된 것은 아닙니다. 별도로 `test_general_ade_memory.py`는 **새 31사례**,
CPU·장치 불필요 21사례와 실제 CUDA 10사례를 통과했습니다. 선택·거부,
실제 상태 바이트, prepared 재사용을 검사하며, CUDA 여덟 사례는
no-grad/inference 예열 뒤 35단계·블록 8/32·나머지 3단계에서 전체 Hessian을
비교합니다. 기존 이산해·미분 기준은 유지했습니다. 연구 도구의 독립 기준해
17검사도 통과했고, 기존 CPU 회귀 여덟 검사는 일반·필름 Decay 메모리,
필름 에너지, PlaneWave 소스 lowering의 해당 NumPy/JAX/Torch 경로를
유지했습니다. 이 집계는 서로 구분하며 전체 CI 통과를 뜻하지 않습니다.

#### 과거 제품 비용 측정

이 여섯 측정은 축소 저장의 스칼라 갱신식 산술 검사를 복원한 제품 커밋
`5dd110ad`의 결과입니다. 공개 호출의 lowering도 측정하므로 이후 추가된
소스·초기 진폭 유효성 검사는 이 시간에 반영되지 않았습니다. 표를 재현하려면
해당 과거 소스를 사용해야 하며, 현재 연구 도구를 실행하면 현재 체크아웃의
비용을 측정합니다. 더 이른 시도도 과거 기록으로 보존했고 해당 후속 측정의
allocated/reserved 최대값은 같았습니다. 이 결과는 일반적인 가속을
입증하지 않습니다.

제품 연구는 Python 3.12.14, Torch 2.14.1+cu130, CUDA 13.0, NumPy 2.5.4,
Windows 11, RTX 4060 Ti(장치 8585216000바이트), Torch CPU 스레드 하나,
float64를 사용했습니다. 각 행은 새 프로세스에서 한 번 예열한 뒤
163단계를 동기화하여 다섯 번 측정했습니다. 전체 격자 재료, Ey Record
하나와 최종 장을 사용하는 균일 초기 진폭·Lorentz strength 미분 사례이며,
모든 정책의 `sum(E_final**2)` 목적함수는 같은 SI 갱신식을 따릅니다.

조회와 정리는 제외합니다. 예열 후와 다섯 번 측정 후에 캐시를 해제하고

해제합니다. 표의 최대값은 시간 측정 실행의 값으로, 별도 비측정 lifecycle·
소유권 실행의 최대값은 포함하지 않습니다. 할당자 값에는 CPU, 드라이버·
화면, 다른 프로세스 메모리가 포함되지 않습니다.

측정한 30회 모두 독립 특성근·Record(`1e-11`), 절대 갱신식 잔차(`1e-12`),
목적함수·재료·진폭 미분(상대 `2e-12`, 절대 0) 검사를 통과했습니다.
최대 Record, 절대 갱신식, 상대 기울기 오차는 각각
`6.106226635438361e-15`, `3.9985376121265404e-16`,
`2.3453478832892504e-13`입니다. 소스 해시는 변하지 않았고 여섯 프로세스
모두 마지막 current allocated/reserved가 0으로 돌아왔습니다. 실제 극점
초기 메모리는 보고량과 같아 32³에서 1572864, 64³에서 12582912바이트였고,
E/H+극점 상태는 각각 3145728, 25165824바이트였습니다.

64³의 별도 순방향 후 보유 allocated는 일반 스캔 1038181888, 블록 8은
534827520, 블록 32는 157309440바이트였으며, 역전파 후 해제 전에는 모두
12587008바이트를 보유했습니다. 이는 논리 상태 payload나 시간 측정 최대값과
다릅니다. 이 기록의 최대값은 대응하는 더 이른 축소 상태 측정과 같고, 과거 원래 상태와
축소 상태의 시간 범위는 겹칩니다. 제품 표는 이 제한된 메모리·시간 관계를
보이며 일반적인 가속, 크기 확장 법칙, 보편적인 최적 체크포인트 블록을
입증하지 않습니다.

64³는 같은 조건의 성공한 32³ 기록을 사용했습니다. 일반/8/32의 reserved
예측량은 2239758336/1308622848/855638016바이트로 4 GiB 상한보다 작았습니다.
각 예열 전 가용 메모리는 7389315072바이트로 추가 1 GiB 여유 조건도
통과했습니다. 예측은 메모리를 예약하거나 부족 실패를 방지한다고 보장하지
않습니다. 이 측정에는 프로파일러를 실행하지 않았습니다.

## 근거와 한계

위 35사례는 기존 일반 장면·관측 파일의 합계입니다. 체크포인트 21사례와
Job 네 사례를 포함한 통합 실행은 60사례가 모두 통과했습니다. 별도의
기본 CPU/JAX 수명주기·통합 Job·마이그레이션 회귀 검사는 53사례가 통과했습니다.

| 검사 | 독립 기준 또는 장치 비교 |
| --- | --- |
| 주기 상자의 균일 전도체, 20단계 | E와 시간 기록의 정확한 SI 전도도 갱신식, 변하지 않는 H; 상대 `2e-14` |
| 전도도와 초기 진폭 미분 | 갱신식의 닫힌형 미분과 상대 `2e-12`; CPU와 CUDA 파라미터 리프 모두 검사 |
| CPML, 평면파, 장 기록·푸리에 장·플럭스를 포함한 슬래브 | 기존 최대값 정규화 무한대 노름 기준 `5e-13`으로 NumPy CPU 비교; prepared 재사용, 바뀐 입력, 이전 결과 보존 |
| 슬래브 유전율과 광원 미분 | NumPy 재료 중앙차분과 상대 `1e-6`, 절대 `1e-8`; 정확한 광원 이차 항등식과 상대 `2e-12` |
| 161단계 Record, Field, Flux 목적함수 | CPU/CUDA 값과 상대 `5e-13`; 광원 이차 항등식과 `2e-11`; 두 간격의 영이 아닌 재료 중앙차분과 `2e-6` |
| x·y·z 법선 슬래브, 열린 3D 펄스, 전도도가 있거나 없는 대각 epsilon·mu | 최대값 정규화 `5e-13`으로 CPU 장 비교; 방향 오차가 상쇄로 숨지 않도록 영이 아닌 상자 플럭스 여섯 면을 개별 비교 |
| 서로 다른 장치의 재료·광원 리프 | Epsilon/mu/conductivity 값과 미분은 CPU와 일치; CPU phase와 CUDA delay 미분은 두 간격의 영이 아닌 NumPy 중앙차분과 상대 `2e-6`으로 일치; 리프 장치 소유권 유지 |
| 고정 초기 패턴과 정밀도 | prepared CPU 텐서 패턴을 수정하면 재사용 무효; 미분 가능한 패턴 거부; float32 호스트 패턴은 정밀도 경고를 유지하며 실행 장은 float64, 입력은 보존하고 진폭 기울기는 원래 float32 CPU 리프로 반환 |
| 입력과 재사용 제어 | 지원 밖 범위는 계획 전에 거부; 준비는 장을 진행하지 않음; 호환되지 않거나 잘못된 재사용 거부; 잘못된 미분 가능 재료는 실패한 validity와 NaN을 유지 |

관측 목적함수는 고정된 SI 스케일 계수를 사용합니다. 실행 장의 노름으로
정규화하거나 장에 의존하는 값을 미분 그래프에서 분리하지 않습니다.
동일한 이산 문제와 그 미분을 검증한 것으로, CPU 일치가 독립 광학 해는
아닙니다. 격자·유한 실행 길이·정밀도 경고는 그대로 표시하며 허용오차나
경고 정책을 완화하지 않았습니다. 축 순열, 열린 3D
펄스, 대각 재료 검사는 유한한 장치 검증 사례를 늘린 것이며 허용하는
기능 종류나 연속체 정확도 주장을 확장하지 않습니다.

[Native CUDA 기록](native-cuda.md)에 측정 Windows/Python/Torch/GPU 환경과
독립 환경 설치가 있습니다. 그 성능 표는 native 엔진의 결과이며 이 일반
장면 실행의 성능이 아닙니다. 일반 실행의 기본값은 기존의 단순 시간 스캔입니다.
아래 메모리 결과는 어떤 입력을 미분하는지에 따라 달라집니다. 보편적인
메모리 절감, 컴파일, 장시간 안정성, 여러 GPU를 검증했다고 주장하지 않습니다.

## 정적 Bloch 근거

이 허용 범위 변경은 기존 복소수 커널과 CPML 갱신식을 사용합니다. 최종 신규
범위는 **중복 없는 66개 사례**이며 CPU 25개, 실제 CUDA 28개, CUDA 장치가
필요 없는 거부 검사 13개입니다. CPU 재료/진폭 AD 사례는 Torch 2.14.1에서
별도로 검증했습니다. 기존 일반 범위 거부 검사 9개는 이 신규 합계와 별개입니다.

| 신규 범위 | CPU | 실제 CUDA |
| --- | ---: | ---: |
| 정확한 이산 모드 | 4 | 4 |
| 재료/진폭 AD | 1 | 2 |
| 수명주기·물리 계약 | 13 | 13 |
| 경사 입사 PlaneWave | 5 | 5 |
| 복소수 CPML 관측값 AD | 2 | 4 |

첫 CUDA 실행은 모드·AD·계약 18개를 5.72초에 통과했고 PlaneWave 실행은
5개를 27.37초에 통과했습니다. 이후 확장한 계약 13개와 관측값 4개가
103.92초에 통과했습니다. 이 실행의 예상 coarse-mesh·유한 관측 창 경고
142개를 그대로 기록했습니다. 나중 계약 재실행은 첫 실행과 겹치므로 고유
합계에 다시 더하지 않습니다. 장치가 필요 없는 13개 검사는 Dipole/벽 제외,
순방향 AD/`torch.func` 래퍼, prepared 재사용 시 primal은 같고 tangent가
있는 forward dual을 다룹니다. 이는 실행 전 거부의 근거이며 CUDA 실행의
근거는 아닙니다.

| 검사 | 독립 기준과 유지한 허용오차 |
| --- | --- |
| 복소수 Yee 모드, 16³, 300단계 | 부호 있는 Bloch 위상과 Periodic 한 축의 세 순환 방향, 전체 Bloch 축 사례; 정확한 E/H 장·기록 `1e-10`, 시간 갱신식 `1e-11`; 위상 생략·반전 대조군은 `1e-4` 초과 |
| 재료·초기 진폭 AD, 16³, 17단계 | 이산 고유주파수와 복소수 절대값 제곱 목적함수의 해석적 미분; 전체 E/H·목적함수·두 미분 상대 `2e-12`, 절대 0; 단순 스캔과 K7·3단계 tail, 서로 다른 장치 리프와 prepared 재사용 |
| 정적 값·수명주기 | 동등한 phase/k 선언의 일치; phase·표현·초기 패턴 변경 시 재사용 거부; CUDA live phase/k와 미검증 Bloch/광원/벽 조합 거부; 짝지은 면, 0 아닌 위상, 복소수 dtype, 광원 파수 일치와 한 셀 검사를 유지 |

AD 기준은 `K_j = 2*sin(k_j*dx/2)/dx`,
`omega = 2/dt*asin(dt*|K|/(2*sqrt(epsilon*mu)))`입니다. 정적 초기 E/H 배열을
고르면 각 live epsilon에서 `E_N = A*E_0*cos(N*omega*dt)`가 성립합니다.
목적함수는 `A**2*mean(abs(E_0)**2)*cos(N*omega*dt)**2`이며 진폭·epsilon의
해석적 미분은 초기화를 미분하지 않습니다. 바꾼 두 리프 묶음으로 이전 결과,
원래 배열과 리프 소유권을 확인합니다. 정확한 이산 모드의 미분 검사이며
연속체나 Bloch 위상 미분의 검증은 아닙니다.

공개 경사 입사 사례는 물리 영역 0.25×0.2×3 µm, 간격 0.05 µm, 24셀 PML과
Gaussian 펄스를 사용합니다. 네 사례가 20° s/p의 양쪽 z 방향을 1100단계
실행합니다. 독립적으로 쓴 파형 변환, 고정 k의 Yee 분산과 엇갈린 이산 편광을
닫힌식으로 사용하며 hard-source부터 probe까지 거리는 선언한 기하에서
구합니다. 공개 초·라디안과 A/m 단위 H를 기준식에 맞춰 명시적으로 변환합니다.
CUDA 실주파수 오차의 최대값은 `5.545210e-7`로 기존 `2e-6` 기준 이내였습니다.
다섯 번째 사례는 극각 30°·방위각 35°의 p 편광을 1600단계 실행하고 기하 시간
단위의 감쇠 contour `omega + 0.4i`를 사용합니다. 오차 `6.135543e-8`로
`3e-6` 기준을 통과했습니다.

CUDA 다섯 실행의 역방향/순방향 최대값 비는 최대 `8.393595e-16`, 입구면
기준 오차는 `1.111734e-15`, 이웃 셀 위상 오차는 `1.347744e-15`로 각각
유지한 `1e-13` 기준보다 작습니다. 여섯 장 성분 모두 검사하며 0 아닌 순방향
하한과 complex128 장치 배치를 확인합니다. 광원 기준은 주 격자 샘플과
비교하고 순방향 파동은 독립 닫힌식과 비교합니다. 이 유한 진공 사례로 모든
입사각·재료·PML 두께나 복소수 관측값 미분을 검증하지 않습니다.

### 복소수 CPML 관측과 광원 미분

추가 83단계 사례는 30°/35° p 편광 PlaneWave, 정적 가로 Bloch 위상,
비분산 슬래브와 4셀 Open-z PML을 사용합니다. 단순 스캔과 K7·6단계 tail을
검사합니다. CPU 두 사례와 실제 CUDA 네 사례가 모두 통과했으며 CUDA
합계에는 두 스캔 정책을 포함합니다.

NumPy 광원 위상 기저 실행 두 개의 복소수 내적으로 다섯 그룹의 실수 Gram
행렬을 만듭니다. 그룹은 최종 E, 최종 H, E/H 기록, Fourier 장 여섯 성분,
전기·자기 입사 기준 이력입니다. 바꾼 두 리프 묶음에서 해석적 광원 진폭/위상
값·기울기·전체 Hessian이 상대 `2e-12`, 절대 0으로 일치합니다. 정적 Bloch
경계 위상의 미분이 아니라 광원 위상의 미분입니다. CPU 진폭과 실행 장치
위상 리프, 보존한 역방향 그래프와 이전 공개 출력 버퍼는 prepared 재사용에도
소유권을 유지합니다.

별도의 Record·Field·Flux 목적함수는 NumPy 값 상대 `5e-13`, 진폭 제곱 관계
`2e-12`, 광원 위상·슬래브 epsilon 중앙 차분 상대 `2e-6`으로 비교하며 모두
절대 허용오차는 0입니다. 각 secant는 파라미터 값의 `1e-4`와 `5e-5` 두
간격을 사용하고 0 아닌 신호·미분 하한을 둡니다. 출력에는 고정 SI 단위
인자만 곱합니다. 짧은 관측 창과 mesh 경고를 유지하며 이 유한 궤적 AD
검사로 PML 반사 정확도나 수렴한 광학 스펙트럼을 검증하지 않습니다.

## PEC/PMC 벽 경계 근거

별도 벽 검증은 CPU 38사례와 CUDA 41사례(새 검사 총 79사례), 기존 거부
대조군 아홉 사례가 통과했습니다. 위의 나머지 제한은 그대로이며 Bloch와
PEC/PMC 벽 조합은 거부합니다. 대칭·불변축 경계는 CUDA 범위 밖입니다.

| 검사 파일 | CPU / CUDA 통과 | 근거 |
| --- | ---: | --- |
| `test_general_cuda_walls.py` | 20 / 20 | 300단계 PEC/PMC 16³ 공동, x/y/z의 양방향 혼합 벽, 각 벽에 닿는 광원 지지 영역 거부. |
| `test_general_cuda_wall_ad.py` | 18 / 21 | 독립 초기 노드 투영, 41단계 초기 진폭·내부 전기·자기 Dipole 미분, prepared 소유권, 벽/Open/PML 상호작용 두 사례. |

공동 기준은 독립 이산 Yee 주파수와 정확한 시공간 엇갈림 장을 사용하며
기존 갱신식 잔차 상대 `1e-11`, 위상·진폭 상대 `1e-10`을 유지합니다.
벽 위치 변이는 갱신식 오차가 `1e-4`보다 커야 합니다. 혼합 PEC/PMC 벽의
실제 길이는 `L - dx/2` 또는 `L + dx/2`이며 둘을 L로 간주하면 실패합니다.
정확한 이산 모드 검사이지 연속체 세분화나 임의의 공동 정확도 주장은 아닙니다.

임의의 영이 아닌 호스트 배열로 첫 curl 전에 초기 투영을 독립 검사합니다.
PEC-low는 접선 E·법선 H, PMC-high는 접선 H·법선 E를 0으로 만듭니다.
PEC-high와 PMC-low는 외부 ghost를 사용하며 저장된 층을 추가로 0으로 만들지
않습니다. 마스크 밖 내부와 사용자 입력은 유지합니다. 41단계 CPU 실행은
단순 스캔이며 CUDA는 블록 7·6단계 tail도 검사합니다. CPU/CUDA 진폭 리프의
이차 항등식은 `2e-12`, 초기 진폭의 NumPy 중앙차분은 `1e-7`입니다.
내부 xyz 전기·자기 Dipole의 전류 모멘트·phase 미분은 두 NumPy 중앙차분과
`1e-7` 및 `1e-10*loss`, 이차 스케일은 `1e-12`, 반 단계 광원 일은
`1e-13`으로 일치합니다. 새 실행과 prepared 재사용은 이전 결과와 입력
소유권을 유지하며 경계 선언이 바뀌면 준비가 무효화됩니다.

추가 두 사례는 8³ 물리 영역에 x PEC, y PMC, z Open·4셀 PML과 전기 Ey
또는 자기 Hy를 함께 둡니다. 같은 41단계에서 CPU 단순 스캔, CUDA 블록 7을
사용합니다. 제한된 장치 비교·미분 검사로 벽/CPML/체크포인트 상호작용을
검사하며, 얇은 padding이 PML 반사 정확도나 복사 정확도를 입증하지는
않습니다. 기존 격자 경고는 유지합니다.

## 공개 슬래브의 독립 검사

`test_general_cuda_airy.py`는 공개 `PlaneWave`, `Field`, `Flux` 인터페이스를
통한 독립 광학 검사입니다. CPU 세 사례와 실제 CUDA 세 사례로 총 여섯 사례가
모두 통과했습니다. 별도 실행이므로 위 60사례에는 포함하지 않습니다. 독립
광학 근거의 범위는 아래 평면 사례로 한정됩니다.
사용하지 않는 DFT 위상 생략과 no-grad 런타임 분기 이후에도 일반 CUDA 광학 세 사례와
별도 periodic 위·아래 입사 슬래브 두 사례가 모두 다시 통과했습니다.
기존 격자 경고는 그대로 표시했습니다.

사례는 진공 속 두께 0.2 um, epsilon 2.25 박막이며 횡방향 주기 경계,
열린 z 경계와 24셀 PML을 사용합니다. 파장 다섯 개는 0.80, 0.90, 1.00,
1.15, 1.30 um입니다. 슬래브·빈 영역 실행은 같은 광원과 관측점을 사용하며
제곱 전에 복소 입사 장을 빼고, 측정한 기준 장으로 광원 스펙트럼을 상쇄합니다.
기준 진폭은 대역 최대값의 0.1보다 커야 합니다. 이산 전파 위상으로 r/t의
기준면을 슬래브 면으로 이동합니다.

복소 r과 t는 기존 독립 이산 Yee Airy 방정식에 대해 최대 절대 `2e-6`,
상대 `1e-5` 오차 안에 있어야 합니다. Flux로 구한 R/T는 장 진폭의 제곱과
절대 `2e-5`로 일치해야 하며 앞·뒤 기준 플럭스에도 같은 기준을 적용합니다.
진공 박막 대조군은 반사가 정확히 0이고 이산 투과 위상은 상대 `1e-12`로
일치해야 합니다. 이 CUDA 경로에 맞춰 새로 정한 허용오차가 아닌 기존 기준입니다.

간격 0.05와 0.025 um 각각에서 푸리에 시간창을 광원 24주기에서 32주기로
늘려도 r/t 변화가 같은 이산 허용오차보다 작아야 합니다. 간격을 절반으로
줄이면 반 셀 보정한 연속체 반사 오차가 3.2~5배 감소해야 하며 거친 격자의
오차는 0.03보다 커야 합니다. 기존 계단 근사·분산 보정을 지우지 않고
검사합니다. 수직 입사의 무손실 박막 하나에 대한 검사이며 일반 기하,
분산, 장시간 안정성이나 광학 미분을 검증하지 않습니다.

## 선택적인 역방향 체크포인트

`Numerics(checkpoint_steps=K)`는 고정 실행 길이의 Torch CUDA에서 양의
정적 정수 블록 길이를 선택합니다. 기본값 `None`은 기존 스캔을 유지합니다.
명시적 체크포인트는 CPU 백엔드, 다른 장치, `Decay`에서 거부합니다. 잘못된
값, 불리언(불리언 텐서 포함), 미분·변환을 거치는 블록 길이는 계획 전에
거부하며 기존 CUDA 기능 범위도 그대로 적용합니다.

역방향 미분 중 블록을 재계산하는 정책이며 메모리 상한은 아닙니다. 관측과
광원 이력은 계속 보존합니다. 블록이 일반 장면의 전체 실행보다 길면 일반
tail만 남습니다. 한 블록으로 처리하는 native 실행기와 이 점이 다릅니다.
스케줄을 바꾸려면 새 numerics로 다시 준비해야 합니다.
`report.resolved['checkpoint_steps']`,
`prepared.contract['resolved_checkpoint_steps']`,
`result.provenance['checkpoint_steps']`에서 선택값을 확인할 수 있습니다.

체크포인트 파일은 실제 CUDA 네 사례를 포함한 21사례가 통과했습니다.
17단계 전도체의 블록 1·64는 독립 SI 갱신식과 전도도·초기 진폭 미분을
보존합니다. 163단계 슬래브의 블록 11은 9단계 tail을 남기며 최종 장,
Record, Field, Flux 목적함수와 재료·광원 미분이 기존 스캔과 일치합니다
(값 상대 `5e-13`, 기울기 상대 `1e-12`). 여러 backward 조회가 그래프를
올바르게 유지하고, 독립적인 리프로 두 번 prepared 재사용해도 이전 결과를
보존합니다. 광원 이차 항등식은 별도로 `2e-11`에서 검사하며, 잘못된 live
재료는 실패한 validity와 NaN을 유지합니다.

입력 검사에는 불리언 Torch 텐서를 블록 길이로 거부하는 회귀 세 사례가
포함됩니다.

Job 네 사례는 고정된 기존 기본 키와 명시적 스케줄의 저장·복원을 검사합니다.
`checkpoint_steps=None`은 v1 Job envelope에서 생략하며 명시적 정수는
직렬화합니다. 선택적 계약과 제한된 미분 일치를 검증한 것으로, 일반 장면의
메모리 측정은 이 합격 검사와 별개입니다.

## 범위를 한정한 2차 미분

`test_general_cuda_higher_order.py`의 실제 CUDA 두 사례가 배정밀도
17단계 균일 주기 전도체에서 통과했습니다. 단순 스캔과 블록 3·2단계 tail을
검사합니다. 목적함수는 최종 Ey 제곱의 평균 `J = A**2 * q**34`이며
`q = (1 - sigma*f)/(1 + sigma*f)`, `f = dt/(2*epsilon0*epsilon)`입니다.
스칼라 유리 갱신식을 독립적으로 미분한 값·기울기·진폭/전도도 순서의 전체
Hessian을 상대 `2e-12`, 절대 0으로 비교하며 혼합 미분의 양쪽 순서를
포함합니다. 실행의 dt와 공통 epsilon0 상수를 사용하므로 미분의 기준이지
시간 간격이나 단위 상수의 독립 검증은 아닙니다.

진폭 리프는 CPU, 전도도 리프는 CUDA에서 시작합니다. Eager
`torch.autograd.grad(..., create_graph=True)` 후 double backward의 미분은
원래 리프 장치로 돌아갑니다. 바꾼 리프로 재사용한 결과는 새 준비와 일치하며
첫 결과는 그대로 유지됩니다. 두 사례는 앞의 1차 미분 검사 합계와 별개입니다.
임의의 기하, CPML, 다른 광원·재료 종류의 Hessian이나 `torch.func` 변환을
검증하지 않습니다.

## Gaussian pulse 파장·대역폭·위상·지연 Hessian

이 검사는 기존 electric Ey Dipole 경로를 사용하며 런타임이나 입력 허용 규칙을
바꾸지 않습니다. 주기적 8³ 격자는 dx 0.05 um, Courant 0.5, 상대 epsilon 2.25,
mu 1.3, 전도도 600 S/m입니다. 고정된 비격자 중심 `(0.013,-0.021,0.007)` um와
전류 모멘트 `I0=1.7e-16` A·m에 `bspline` 또는 `tent`를 사용합니다. 초기 장은
0이고 17·41단계를 실행하며 CUDA 체크포인트 7의 나머지는 3·6단계입니다.

`T=1 um/c0`, `k=sqrt(-2*log(1e-3))`, 무차원 좌표 `p=(l,b,phi,d)`에 대해
물리 입력은 다음과 같습니다.

```text
wavelength = 2*l um
frequency_sigma_hz = 0.08*b/T
phase = phi radians
delay = BASE_DELAY + T*d seconds, BASE_DELAY = -k*T/(2*pi*0.08).
```

지연 기준값은 고정입니다. 대역폭을 바꾸면 포락선 폭과 피크 시각
`delay+k/(2*pi*frequency_sigma_hz)`가 함께 바뀌며 피크를 고정하도록
재중심화하지 않습니다. 두 점은 `(1,1,0.4,0.12)`와 `(0.97,1.01,-0.2,0.16)`입니다.
um·Hz·radian·second 단위의 물리 좌표 x는 `x=offset+S*p`,
`S=diag(2,0.08/T,1,T)`이므로 `g_p=S*g_x`, `H_p=S*H_x*S`입니다. 물리 Hessian은
각 원소를 두 좌표의 스케일로 나누어야 합니다. 파장을 m로 쓰면 첫 인자는 `2e-6`입니다.

독립 기준해는 Gaussian 전류와 네 1차·열여섯 2차 미분을 해석적으로 씁니다.
전기 전류 시각 `(n+0.5)*dt`에서 `u=t-delay-k/(2*pi*f_sigma)`,
`v=2*pi*f_sigma*u`, `Q=-v²/2+i*(2*pi*c0*u/wavelength+phi)`이면
`I=I0*Im(exp(Q))`입니다. 1·2차 forcing 미분은 `Q_i`와 `Q_i*Q_j+Q_ij`를
포함합니다. 독립 cardinal cubic 또는 폭 두 셀의 tent stamp로 모멘트·중심을
검사하고, 값 1개·1차 4개·대칭 2차 10개의 15 lane을 명시적 주기 인덱스
Yee 갱신으로 전파합니다. SI 전류 계수는
`-dt/(epsilon0*(epsilon+sigma*dt/(2*epsilon0))*dx³)`입니다.
제품 waveform·stamp·curl·계수·AD helper는 기준해에 사용하지 않습니다.

목적함수는 `mean((drive/I0)²)`와 가중 최종 E·Z0H 및 여섯 Record 제곱 평균의
두 가지입니다. 가중치는 `(1,0.7,1.3,0.6,1.1,0.9)`, 성분 정규화는 `1/6`,
Record 인자는 `1/4`, Record 시각 가중치는 `1+0.2*n/N`입니다. 값·네 기울기·
완전한 4×4 Hessian과 양쪽 혼합 미분 순서에 상대 `2e-12`, 절대 0을 씁니다.
장은 전체 배열 최대값으로, Record는 E/H별 그룹 최대값으로 정규화하므로
구조적으로 0인 Hy도 0으로 나누지 않고 검사합니다. 순방향 오차는 `2e-12`,
시각은 `2e-14`입니다.

독립 기준해는 고유 14사례를 검증했습니다. 첫 secant 실행은 13통과·1실패였으며,
정규화 좌표의 절대 간격 `2e-5`에서 혼합 Hessian 차분 오차 `3.96673119e-6`가
`2e-6`을 넘었습니다. 간격을 절반으로 하면 절대 오차가 약 4배 줄어 중앙차분의
`O(h²)` 절단오차와 일치했습니다. 최종 절대 간격 `1e-5`·`5e-6`은 같은
`2e-6` 기준을 통과했고 최대 오차는 `9.91691679e-7`입니다. 목적값으로 정규화한
최소 Hessian 원소는 `0.0793395795`로 기존 비자명성 하한 `1e-6`보다 큽니다.
원실패를 보존했으며 직접 미분이나 secant 허용오차를 늘리지 않았습니다.
일곱 forcing·stamp mutant 모두 `1e-4` 분리 하한을 통과했습니다.

공개 검사는 CPU/CUDA plain 및 CUDA 체크포인트를 비교하며 같은 리프로
점 0 → 점 1 → 점 0을 재사용합니다. 파장·위상 리프는 CPU에, 대역폭·지연
리프는 실행 장치에 둡니다. 미분 소유권과 과거 출력·기울기·Hessian 텐서의
불변성, 광원 일과 원래 값 복구를 검사합니다. 별도의 새 준비 um/nm 쌍은
물리적 동등성을 검사합니다. 정적 cutoff·중심 변경, 비스칼라 band, 주기 수
기반 실행 길이에서의 파장 변경은 stepping 전 거부하는지 확인합니다.
**고유 32사례가 모두 통과**했습니다. 독립 기준해 14개, 공개 CPU 9개
(solver·단위 5개와 실행 전 거부 4개), 실제 CUDA 9개(Hessian·재사용 8개와
단위 쌍 1개)입니다. 공개 CPU는 3.39초·경고 8개, CUDA는 27.42초와
traced band의 `CoarseMeshWarning` 9개로 통과했습니다. 이 경고는 host 계획
단계의 검사를 설명하며 후속 pole-free 런타임 certificate와는 별개입니다.
독립 측정한 거친 격자 오차를 뜻하지 않습니다.

| 기록된 CUDA 비교 | 최대 상대·정규화 오차 | 기준 |
| --- | ---: | ---: |
| 주검사 8개의 순방향 장·Record·광원 drive | 2.72025560e-14 | 2e-12 |
| 두 목적값 | 1.31006317e-14 | 2e-12 |
| 네 기울기 | 6.06181771e-14 | 2e-12 |
| 완전한 4×4 Hessian | 9.27036226e-14 | 2e-12 |

미분 감사는 주 CUDA 검사 8개 각각의 세 방문·두 목적함수 기록을 독립적으로
재계산했습니다. 별도 CUDA 단위 쌍은 assertion을 통과했지만 이 최대값에
포함할 오차를 기록하지 않았습니다. 공개 CPU의 기록된 순방향 최대 오차는
`2.72594056e-14`이며, CPU 미분 assertion도 통과했지만 별도 최대값은
기록하지 않았습니다. 검증 전후 소스 해시는 변하지 않았습니다.

이는 이산 forcing과 eager double-backward 검증이며 방사 정확도·연속체 수렴·
임의 펄스 최적화·변환 지원 검증이 아닙니다. 두 기준점은 독립적으로 양의
스펙트럼 하한과 매질 내 최단 cutoff-band 파장당 10셀 초과를 만족합니다.
후속 [live Band cutoff guard](#live-band-carrier-cutoff)는 carried band의
`f0`·`k*f_sigma`가 유한하고 엄격한 `f0 > k*f_sigma`를 만족하는지 검사합니다.
후속 [pole-free 공간 certificate](#live-band-pole-free-spatial-resolution)는 선언된
재료에 극점이 없을 때 현재 값의 기존 하한을 검사합니다. 극점이 있으면 이전
해상도 경로를 유지합니다. 어느 predicate도 연속체 정확도나 최적화 전체 범위를
보증하지 않으므로 독립 세분화와 다른 파형 중간 연산의 범위 제어가 필요합니다.

## 네 좌표의 projected pulse fitting

이 회귀 검증은 기존 electric Ey Dipole 경로를 대상으로 하며 runtime이나
admission 규칙을 바꾸지 않습니다. 앞의 독립 15-lane 펄스 기준해에 `bspline`
stamp, 주기 8³ 격자, 41단계와 고정 매질을 사용합니다. 정규화 목표는
`p*=(0.985,1.005,0.1,0.14)`, 두 시작점은 `(1,1,0.4,0.12)`와
`(0.97,1.01,-0.2,0.16)`입니다. 파장·대역폭·위상·지연은 앞서 설명한 물리
좌표 변환과 고정 지연 기준값을 유지합니다.

F는 최종 E·Z0H, R은 H에 Z0를 곱한 여섯 Record입니다. 성분 가중치는
`(1,0.7,1.3,0.6,1.1,0.9)`, Record 시각 가중치는 `1+0.2*n/41`이며
잔차 목적함수는 다음과 같습니다.

```text
C = mean(w_R * R_target**2) + 0.25*mean(w_F * F_target**2)
L(p) = [mean(w_R * (R(p)-R_target)**2)
        + 0.25*mean(w_F * (F(p)-F_target)**2)] / C.
```

목표와 잔차 값·기울기·전체 Hessian은 독립 SI 기준해에서 구하며 잔차와
2차 미분의 곱 항도 포함합니다. HVP 방향은 `(1,-0.5,0.25,0.75)`입니다.
잔차가 0인 목표에서 Gauss–Newton Hessian을 G라 두고
`D=diag(1/diag(G))`, `eta=0.1/lambda_max(sqrt(D)*G*sqrt(D))`로 정합니다.
이 값들은 trajectory 전에 고정되며 좌표별 SGD 학습률은 `eta*D_ii`입니다.

열두 번의 각 갱신에서 먼저 `q=p-eta*D*g`를 제안한 다음 q를 고정 정규화
box `[0.94,1.04] × [0.97,1.04] × [-0.5,0.7] × [0.08,0.2]`에 성분별로
투영합니다. optimizer는 `foreach=False`와 `zero_grad(set_to_none=True)`를
사용합니다. 투영은 autograd 밖에서 수행합니다. 미분 비교 대상은 각 평가점의
매끄러운 잔차이며, 비매끄러운 투영이나 전체 최적화 mapping은 아닙니다.

원래 비제약 사전 실행은 두 번째 seed의 두 번째 제안에서 파장 좌표가 약
`0.92887`로 `0.94`보다 작아져 box를 벗어났습니다. 이는 trajectory 정의역
실패이며 미분 불일치가 아닙니다. projected 규약은 그 검증 전에 별도로
명시했고, 원시도를 보존하며 미분 허용오차를 늘리지 않았습니다.

**새 고유 14사례가 모두 통과**했습니다. 독립 기준해 control 8개, 공개 CPU
plain trajectory 2개, 실제 CUDA trajectory 4개입니다. CUDA는 두 seed 각각
plain 또는 체크포인트 7을 사용하며 tail은 6입니다. 공개 CPU 실행은
9.76초·경고 4개, CUDA는 34.71초·경고 4개로 통과했습니다. 이는 테스트 실행
시간이며 성능 측정값이 아닙니다. 검증 전후 소스와 기존 미분 기준은 유지했습니다.

파장·위상은 caller CPU에, 대역폭·지연은 실행 장치에 둡니다. 각 갱신에서
raw SGD 제안과 투영한 점을 독립 trajectory와 비교하고, 실제 local point의
잔차 값·기울기·HVP도 검사합니다. 상대 허용오차는 `2e-12`, 절대 허용오차는
0입니다. 같은 리프와 과거 detached 출력을 유지하며 `.grad`를 비우고, 다음
반복 전에 live 결과·미분 graph의 weak reference가 모두 해제되었는지 검사합니다.

독립 감사에서 여섯 trajectory와 72개 갱신을 재계산했습니다. 최대 상대오차는
목적값 `1.55049897e-13`, 기울기 `1.78910054e-13`, HVP `5.13582612e-14`이며,
기록된 순방향 정규화 최대 오차는 `1.04404066e-14`입니다.

| Seed | 시작 목적값 | 12번 갱신 후 목적값 | 투영이 적용된 갱신 수 |
| --- | ---: | ---: | ---: |
| 0 | 0.122965706571319 | 0.021001548655822 | 0 |
| 1 | 0.151257104004487 | 0.011733149330523 | 11 |

두 번째 trajectory는 파장 좌표 경계 `l=0.94`에서 끝납니다. 잔차 감소는 목표

열두 번의 갱신 후 검사에서 allocated 60,416바이트를 기록했습니다. 그 출력을
해제하면 목표 텐서와 caller 리프가 남아 있는 persistent baseline으로 복귀했으며,
전체 allocation이 0이 된 것은 아닙니다. 이 값들은 live storage 검사이며
peak-memory 측정이나 체크포인트 시간·메모리 이득의 근거가 아닙니다.
범위는 이 이산 fitting 회귀 검증이며 보편적 수렴·연속체 역문제 정확도·공개
optimizer API를 뜻하지 않습니다.

검증된 환경에서 독립 control과 공개 여섯 trajectory를 재현할 수 있습니다.

## CPML 진폭/위상 2차 미분

공개 `test_general_cuda_cpml_higher_order.py`는 여섯 Open 면, 4셀 PML을 둔 균일
진공 상자에서 전기·자기 Dipole을 41단계 실행합니다. 단순 스캔과 CUDA K7의
6단계 tail에 같은 기준을 사용합니다. 위상 0과 pi/2의 NumPy 두 기저 실행으로
Gram 행렬 `G`를 구하면 진폭 `A`, `u = (cos(phi), sin(phi))`의 제곱 목적함수는
`A**2 * u.T G u`입니다. 이 식을 해석적으로 미분한 값·기울기·전체 진폭/위상
Hessian을 상대 `2e-12`, 절대 0으로 비교합니다. CPU 진폭과 실행 장치 위상
리프, 바꾼 입력의 prepared 재사용과 이전 결과 보존으로 그래프 소유권을
검사합니다. 같은 공간 이산화를 공유하는 기준이므로 제한된 미분 검증이며
PML 반사 정확도나 임의 재료·기하 Hessian의 독립 기준은 아닙니다.
유지한 함수형 runtime에서 6개 모두 통과했습니다. CPU 2개와 실제 CUDA
4개이며 실행 시간은 21.71초였습니다. 앞의 전도체 Hessian 사례와 별개의
검증 결과입니다.

### 범위를 한정한 CPML 최적화 실험: 미채택

할당량 감소를 보이지 않아 runtime 최적화를 채택하지 않았습니다. 함수형
CPML 구현은 유지하고 독립 미분 검사는 보존합니다.

## 체크포인트 비용 실측

prepared 전도체 사례는 native 기록의 환경, Torch CPU 디스패치 한 스레드,
CUDA float64 장, 간격 0.05 um, epsilon 2.25, 전도도 600 S/m,
초기 E = (0, 1, 0), 진폭 1.2를 사용합니다. 모든 면은 주기 경계입니다.
163단계 동안 한 지점의 Ey 기록과 최종 장을 보존합니다. 목적함수는 최종
전기장의 제곱합입니다. 진폭만 미분하는 그래프와 진폭·전도도를 함께
미분하는 그래프를 비교하며 live 스칼라 리프는 CUDA에 있습니다.

각 설정은 한 번 예열한 뒤 동기화한 반복 세 번을 측정합니다. 시간에는
live 리프 생성, prepared 실행, 목적함수와 역방향 미분을 포함하고 준비,
호스트 스칼라 복사, JSON 쓰기는 제외합니다. 메모리는 예열·가비지 수집·
할당자 캐시 해제 후 세 반복의 최대값입니다. 모든 행의 시작 할당량은
0이었습니다. allocated·reserved 최대값은 Torch 할당자 수치이며 드라이버·
화면 메모리를 제외합니다. CPU 메모리는 측정하지 않았습니다. 준비를 포함하며
물리 문제도 다른 native 표와 이 시간을 직접 비교할 수는 없습니다.

측정한 16설정 모두 완료했고 모든 반복에서 해당 검사를 통과했습니다.
독립 SI 갱신식은 `q = (1 - sigma*f) / (1 + sigma*f)`,
`f = dt / (2*epsilon0*epsilon)`, 목적함수는
`J = size**3 * amplitude**2 * q**(2*steps)`입니다. `2*J/amplitude`와
`dq/dsigma = -2*f/(1 + sigma*f)**2`를 사용한 해석적 전도도 미분을
상대 `2e-12`, 절대 0으로 검사합니다. 단순 스캔과의 일치와 별개로 두 미분
그래프를 모두 독립적으로 검증합니다.

시간은 초 단위 중앙값이며 메모리는 allocated/reserved MiB(2**20바이트)입니다.
`None`은 단순 스캔, 블록 8은 20블록과 3단계 tail, 블록 32는 5블록과
3단계 tail이며 블록 200은 일반 163단계 tail만 남깁니다.

| 격자 | 블록 | 진폭 시간 | 진폭 메모리 | 진폭 + 전도도 시간 | 진폭 + 전도도 메모리 |
| --- | --- | ---: | ---: | ---: | ---: |
| 16³ | None | 0.487020 | 1.037 / 2 | 0.518653 | 31.321 / 32 |
| 16³ | 8 | 0.708443 | 5.015 / 6 | 0.737885 | 6.207 / 8 |
| 16³ | 32 | 0.673048 | 2.174 / 4 | 0.697212 | 7.865 / 10 |
| 16³ | 200 | 0.519046 | 1.037 / 2 | 0.499353 | 31.321 / 32 |
| 32³ | None | 0.499816 | 8.255 / 12 | 0.537487 | 250.509 / 334 |
| 32³ | 8 | 0.667726 | 39.796 / 54 | 0.728847 | 49.301 / 66 |
| 32³ | 32 | 0.645770 | 17.268 / 24 | 0.661251 | 62.771 / 84 |
| 32³ | 200 | 0.474110 | 8.255 / 12 | 0.514292 | 250.509 / 334 |

32³ 재료 미분 그래프에서 블록 8은 할당 최대값을 5.08배 줄였지만 중앙값
시간을 0.537487초에서 0.728847초로 늘렸습니다. 같은 물리 문제에서 진폭만
미분하면 할당 최대값이 8.255 MiB에서 39.796 MiB로 늘었습니다. 어떤 리프가
미분을 요구하는지에 따라 저장·재계산의 비용 관계가 달라집니다. 이 사례가
보편적인 최적 블록을 정하거나 다른 장·관측·광원 이력의 절감을 보장하지 않습니다.

표는 두 로컬 JSON 실행을 옮긴 것이며 원시 머신 기록은 이 페이지에 배포하지
않습니다. 진폭 전용 실행의 측정기 SHA-256은
`ffb6cad9975326b2bcd1ddd240dd4351df4ea074cbce429675ff747c1d2a2263`,
전도도 실행은 재료 미분 검사를 추가한
`997bf8c7e4de01e6dca1e2469d84a6305aa6e660a32ce1a21388c65a47496848`입니다.

### 별도의 64³ 재료 미분 측정

이후 실험은 같은 163단계 전도체 사례만 64³으로 키워 진폭·전도도를 함께
미분했습니다. 정책 8, 32, None을 이 순서대로 새 프로세스에서 하나씩
실행하며 각 한 번 예열하고 동기화한 반복 다섯 번을 측정했습니다. Torch
CPU 디스패치 한 스레드와 같은 prepared 호출 시간 경계를 유지했습니다.
모든 반복에서 독립 SI 목적함수와 두 미분 검사를 상대 `2e-12`, 절대 0으로
통과했으며 기록한 값과 기울기는 모든 정책에서 정확히 같았습니다.

| 블록 | 중앙값 초 [최소–최대] | 최대 allocated 바이트 | 최대 reserved 바이트 |
| --- | ---: | ---: | ---: |
| 8 | 0.700060 [0.681144–0.727873] | 413192192 | 463470592 |
| 32 | 0.701149 [0.660019–0.751319] | 526407680 | 589299712 |
| None | 0.549679 [0.535557–0.623938] | 2101355520 | 2350907392 |

이 사례에서 두 체크포인트 정책은 단순 스캔보다 최대 할당량을 줄이고
중앙값 시간을 늘렸습니다. 두 체크포인트 시간 범위는 겹치므로 블록 8과 32의
시간 순위를 신뢰성 있게 정하지 못합니다. 다른 실행 길이, 미분 입력, 광원
이력이나 관측기 부하를 검증한 것은 아닙니다.

각 예열 전 free/total 장치 메모리는 7408189440/8585216000바이트였습니다.
시작 allocated·reserved는 0이며 매 반복 후 allocated는 0으로, 최종 가비지
수집·캐시 해제 후에는 둘 다 0으로 돌아왔습니다. 시작값이 같아 최대 절댓값과
증분 최대값이 같으며 드라이버·화면·다른 프로세스 메모리는 제외합니다.
정리는 시간 측정 밖입니다.

측정기는 기존 32³ 재료의 reserved 최대값에 셀 수 8배와 여유 계수 1.5를
곱해 예측합니다. 8/32/None의 예측은 약 0.773/0.984/3.914 GiB입니다.
예측이 4 GiB를 넘거나 가용 메모리가 예측+1 GiB보다 작으면 거부합니다.
이는 예산 추정이며 메모리 예약이나 부족 실패 방지 보장이 아닙니다. 다른
사용자가 검사 후 가용 메모리를 바꿀 수 있습니다. 확장은 64³·163단계·
재료 미분과 프로세스당 정책 하나만 허용합니다. 로컬 JSON 기록의 측정기
SHA-256은 `6aaed9733821a062f28fae6b6defa1f8161c1e98095af0f71daa5ce68238a6fa`입니다.

## 요청한 DFT 위상만 계산

관측 호출은 요청하지 않은 장의 위상을 생략합니다. Ey 전용 관측기는
사용하지 않는 H 위상을 계산하지 않습니다. 같은 장의 성분끼리 위상을
공유하던 기존 동작은 유지합니다. 전기장은 `(n+1)*dt`, 자기장은
`(n+0.5)*dt` 시각을 유지합니다. 위상 점화식 근사나 시간 단계 사이의
캐시는 없습니다. 변경 후 CPU 검사 37사례가 통과했으며, 새 독립 오프라인
구적·위상 민감 미분 21사례와 고정 관측 기준값·기존 시간 위치 변이 검사를
포함합니다. 전기장 전용·자기장 전용·혼합 성분의 실수·복소 이력을 NumPy,
JAX, Torch에서 검사합니다.

제한된 `monitor_cost.py` 실험은 같은 RTX 4060 Ti 환경, CPU 디스패치 한
스레드, 4×4×84 격자, 128단계, 12셀 PML, 세 파장의 Ey Field 두 개와
Flux 두 개를 사용했습니다. 두 실행 모두 `torch.no_grad()`와 단순 스캔을
사용했습니다. 예열 한 번 후 동기화한 prepared 실행 다섯 번으로 아래 시간을
측정하고, **별도의 계측 실행 한 번**으로 연산 횟수를 셌습니다. 시간에는 live
검사, lowering, 결과 변환을 포함하며 최초 준비, 결과 검사, 호스트 복사,
프로파일링은 제외합니다.

| 프로파일 `aten::exp` 호출 | 1025 | 769 |
| 프로파일 `aten::mul` 호출 | 5888 | 5120 |
| 최대 allocated / reserved 바이트 | 420864 / 2097152 | 420864 / 2097152 |

지수 256회·곱셈 768회 감소는 128단계에서 단계마다 쓰지 않는 H 위상
두 개를 생략한 결과와 일치합니다. 모든 배치·dtype·유한값·실행 validity 검사를 통과했습니다.
기록한 장 최대값과 플럭스 요약은 전후 정확히 같았지만 전체 장의 동일성
검사는 아닙니다. 짧은 시간창에는 약한 초기 펄스만 있으므로 독립 광학 정확도
근거가 되지 않습니다. 시작 할당량은 0이며 최대값은 드라이버·화면·CPU
메모리를 제외합니다. 프로파일러의 shape·메모리 기록은 비용과 텐서 수명을
바꾸며 포괄적인 CPU·장치 시간을 더해서는 안 됩니다.

시간 범위가 겹칩니다. 관측한 중앙값으로 통계적으로 유의하거나 보편적인
속도 향상을 입증하지 않으며 최대 할당량도 줄지 않았습니다. 표는 로컬
기록을 옮긴 것이며 원시 머신 trace를 배포하지 않습니다. 기록한
`src/wavebit/fdtd/_kernel/observe.py` SHA-256은 미사용 위상 생략 전
`23e5a6878f8ee14457c1cbcec422fba4f3b197ed9bb55ef4175b1b12f8988a83`,
생략 후
`709828e0ffa334200d51ab100476f403baeaf05bd2ecb71c9b0c9f0d80cb9f01`입니다.
이 실험은 no-grad 체크포인트 디스패치 변경 이전에 수행했습니다.

### 범위를 한정한 DFT addcmul 실험: 미채택

`91200897` 기준의 별도 실험은 DFT의 함수형 곱셈·덧셈을 입력을 변경하지
않는 `torch.addcmul`로 바꾸었습니다. 중간 dtype 승격이 달라지는 경우는
메타데이터 검사로 원래 식을 유지했습니다. CPU·CUDA 기본 연산 각각 30사례,
독립 구적·미분 CPU 9사례와 고정 Bloch 기준 1사례, CUDA 관측·미분 6사례(142.21초, 예상한
성긴 격자·미감쇠 경고 190개), CUDA Airy 3사례(107.25초, 격자 경고 6개)가
통과했습니다. 이 수치 검증이 성능 이점을 입증하는 것은 아닙니다.

위와 같은 환경과 4×4×84 격자·128단계·일반 no-grad 관측 사례를 사용하고,
전체 배열 비교를 위해 최종 E/H도 반환했습니다. 각 행은 새 프로세스에서
한 번 예열하고 동기화한 prepared 호출 다섯 번을 측정한 것입니다. 최초
준비, 호스트 복사, 실행 후 수치 검사, 정리와 프로파일링은 시간에서 제외하되
prepared 호출 안의 live 검증은 포함합니다. 반복
사이 결과를 해제하며 첫 측정 이후 allocator 캐시를 유지합니다. 두 번째
짝은 실행 순서를 뒤집었습니다.

| 실행 순서 | 구현 | 중앙값 초 [최소–최대] |
| --- | --- | ---: |
| 첫 짝, 첫째 | 원래 식 | 0.5814155 [0.5355944–0.6884793] |
| 첫 짝, 둘째 | 후보 | 0.6112528 [0.5513491–0.6458652] |
| 역순 짝, 첫째 | 후보 | 0.5895994 [0.5594044–0.6366238] |
| 역순 짝, 둘째 | 원래 식 | 0.5563477 [0.5421061–0.6044896] |

네 시도 모두 관측·최종 장 전체 배열의 NumPy 비교를 기존 최대값 정규화
`5e-13` 기준으로 통과했고(최대 오차 `5.207610346140793e-16`), 결과 소유권
검사도 통과했습니다. 측정 중 최대 allocated/reserved는 모두
420864/2097152바이트이고 마지막 정리 후 둘 다 0이었습니다. 별도 한 번의
프로파일에서 `aten::mul`은 5120→3840, `aten::add`는 2603→1323,
`aten::addcmul`은 0→1280으로 바뀌었으며 `aten::copy_`는 912로 같았습니다.
두 짝의 시간 범위가 모두 겹치고 실행 시간·allocator 최대값의 이점을
보이지 않아 연산 수 감소만으로 채택하지 않았습니다. Runtime은 원래 식을
유지합니다. 후보 코드와 원시 머신 기록은 여기서 배포하지 않습니다. 이
제한된 실험으로 시간 차이의 원인이나 연산 사이의 일반적인 우열을
확정하지 않습니다.

## 체크포인트 정책이 있는 순방향 전용 실행

`torch.no_grad()` 또는 `torch.inference_mode()`로 Torch 기울기 기록을
끄면 스케줄이 있는 스캔도 일반 순방향 경로를 사용합니다. 역방향 재계산에
사용하는 블록 복사와 체크포인트 래퍼를 생략합니다. 요청한 정책은 보고서,
prepared 계약과 결과 provenance에 유지하며 같은 prepared 객체를 기울기
기록이 켜진 상태에서 실행하면 다시 사용합니다. 입력 허용 범위를 바꾸거나
순방향 결과를 나중에 미분 가능한 결과로 만드는 기능은 아닙니다.

이후 실행은 확장한 체크포인트 파일 23사례와 관측 미분 두 사례로 총
25사례가 통과했습니다. 앞의 60사례 합계를 수정한 것이 아닌 별도 결과입니다.
새 컨텍스트 두 사례는 163단계·블록 11에서 최종 E/H, Record, 푸리에 E/H,
Flux, 광원 이력을 두 기울기 비활성 컨텍스트의 단순 스캔과 비교합니다.
CPU 진폭과 CUDA 재료 리프는 사용자가 소유하며 변하지 않습니다. 이후 새
리프로 미분 가능한 재사용을 하여 목적함수 네 개, 보존한 backward 그래프,
광원 이차 항등식, 기울기의 장치 소유권, 이전 결과의 불변성을 검사합니다.
값 상대 `5e-13`, 미분 `1e-12`, 광원 항등식 `2e-11` 기준을 유지합니다.
기존 JAX/Torch 체크포인트 스펙트럼 미분 네 사례도 런타임 변경 후 통과했습니다.

별도 CUDA 실험은 요청한 위상만 계산하는 동작을 고정하고 같은 짧은 관측 사례를
16×16×84 격자, 128단계, 블록 8, `torch.no_grad()`로 실행했습니다.
한 번 예열한 뒤 위에서 명시한 시간 경계로 동기화한 비계측 반복 다섯 번을
측정했습니다. 두 버전 모두 모든 수치 검사를 통과했으며 기록한 장 최대값·
플럭스 요약은 정확히 같았습니다.

| 항목 | 순방향 경로 분기 전 | 순방향 경로 분기 후 |
| --- | ---: | ---: |
| 중앙값 초 [최소–최대] | 0.584975 [0.553745–0.626643] | 0.548744 [0.532387–0.580045] |
| 최대 allocated 바이트 | 7394304 | 5763072 |
| 최대 reserved 바이트 | 8388608 | 8388608 |

시간 범위가 겹치므로 중앙값만으로 일반적이거나 통계적으로 유의한 속도
향상을 입증하지 않습니다. 이 순방향 전용 실측 사례의 최대 allocated는
감소했지만 reserved는 같았습니다. 시작 allocated·reserved는 모두 0이며
드라이버·화면·CPU 메모리를 제외한다는 제한도 같습니다. 짧은 시간창의 요약
일치는 전체 장 비교나 광학 검증이 아닙니다. 로컬 기록의
`src/wavebit/fdtd/_runtime.py` SHA-256은 분기 전
`048e38423a374b7880e84f6abb8fef7e5cc2a077a7bce739e4b911bc6e57dcfa`,
분기 후
`6a3a0849bb5527e109b6c7c91d02e9c668c955a6f8a784bab5841f1f1467d11d`이며
원시 머신 기록은 여기서 배포하지 않습니다.
