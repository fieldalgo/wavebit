# JAX·Torch 역방향 미분의 메모리 상한

FDTD 실행을 역방향 모드로 미분하면 보통 매 시간 단계의 중간값을 모두 보관합니다. 그래서
기울기 계산의 메모리가 단계 수에 비례해 커집니다. `Numerics(checkpoint_steps=K)`는 이
메모리를 재계산으로 바꿉니다. 이 기록 이전에는 이 정책을 Torch CUDA 경로에서만, 한 단계짜리
블록으로만 허용했습니다. 이제 JAX와 Torch에서, CPU와 Torch CUDA 경로 모두에서 허용합니다.
스케줄은 중첩 구조이며, 메모리는 단계 수의 로그에 비례해 늘어납니다.

시험: `tests/fdtd/test_checkpoint_memory.py`, 그리고 `tests/fdtd/test_general_ade_ad.py`와
`tests/fdtd/test_general_ade_record_ad.py`의 CPU `cpu-k3-nested` 사례.

## 계산 전에 등록한 합격 기준

- 체크포인트를 쓴 기울기는 일반 스캔의 기울기와 float64에서 상대 `1e-12` 이내로 일치합니다.
  JAX와 Torch CPU 모두 해당하며, NumPy 순방향 실행의 중심 차분과도 일치합니다.
- 기울기 계산의 최대 메모리는 단계 수가 아니라 구간 길이로 정해집니다. 두 실행 길이의 메모리
  비율로 보입니다. 시간은 보고하지 않습니다.
- 기존 골든 값은 그대로입니다. `tests/references/fd_golden_stage*.npz`는 다시 만들지
  않았습니다.
- 새 시험마다 제품 코드를 일부러 망가뜨려 시험이 실패하는지 확인했습니다.

## 스케줄

`K`는 구간(segment) 길이입니다. `K` 단계 이하의 실행은 일반 스캔입니다. 더 긴 실행은
`unit` 단계짜리 구간으로 나눕니다. `unit`은 실행 길이보다 작은 `K`의 거듭제곱 중 가장 큰
값입니다. 각 구간은 체크포인트되며, 한 단계 아래에서 같은 방식으로 다시 나뉩니다. 나머지
단계도 같은 방식으로 이어서 처리합니다. 따라서 `K**L` 단계의 실행은 최대 약 `L * K`개의
상태와 `K` 단계 스캔 하나의 중간값만 보관하고, 순방향 계산을 `L + 1`번 수행합니다. 이전의
한 단계 스케줄은 `steps / K`개의 상태를 보관했습니다.

이것은 균일 다단계 스케줄이며, A. Griewank와 A. Walther의 최적 이항(binomial) 스케줄은
아닙니다: "Algorithm 799: Revolve: an implementation of checkpointing for the reverse or
adjoint mode of computational differentiation", *ACM Transactions on Mathematical
Software* 26(1), 19-45 (2000). Revolve는 보관 상태 `s`개와 재계산 `r`번으로 `C(s + r, s)`
단계에 도달합니다. 균일 스케줄은 `s = L * K`, `r = L`로 `K**L` 단계에 도달하며, 이는 그
한계 안에 있습니다. 균일 스케줄을 택한 이유는 각 단계가 고정 길이 스캔 하나이기 때문입니다.
그래서 JAX는 revolve 스케줄처럼 매 단계마다가 아니라 단계(level)마다 본문 하나만 추적합니다.
`K = 1`이면 모든 시간 단계가 한 단계짜리 구간이 됩니다.

JAX에서 각 구간은 `lax.scan`을 감싼 `jax.checkpoint`입니다. Torch에서 각 구간은 사용자 정의
`autograd.Function` 하나이며, 입력 상태만 보관하고 역방향에서 자신을 재계산합니다.

## Torch에 별도 구간이 필요했던 이유

처음 Torch 구현은 `torch.utils.checkpoint`(non-reentrant)를 중첩했습니다. 기울기는 맞았지만
메모리는 제한되지 않았습니다. non-reentrant 체크포인트는 각 단계가 저장한 텐서는 버리지만
각 단계의 자동미분 그래프 노드는 남겨 둡니다. 순방향만 실행해도 그래프는 격자 크기와 거의
무관하게 단계마다 약 80 kB씩 커졌습니다. 1,024 단계 후 10 x 10 x 48 격자에서 79 MB,
20 x 20 x 48 격자에서 97 MB였습니다. 12,000 단계라면 역방향을 시작하기도 전에 그래프만
약 1 GB를 차지합니다.

`Segment`는 그래프 노드 하나입니다. 그 안의 그래프는 해당 구간의 역방향이 실행되는 동안에만
존재합니다. `autograd.Function`이므로 단계가 읽는 모든 살아 있는 텐서가 입력이어야 합니다.
클로저로만 단계에 전달된 텐서는 기울기를 받지 못합니다. 그래서 실행기는 실행 매개변수를
`scan`에 인수(`params=`)로 넘기며, 매개변수 없이 체크포인트된 Torch 스캔은 오류를 냅니다.

`create_graph=True`일 때 재계산은 저장된 입력의 새 view에서 시작합니다. 입력 자체에서
시작하면 `autograd.grad`가 그 입력을 따라 이전 구간까지 거슬러 올라가, 이 구간의 미분 대신
전미분을 돌려줍니다. 17 단계 장난감 스캔에서 `K = 3`으로 실행하자 기울기가 6배 크게
나왔습니다. 아래의 정확한 헤시안 시험이 이 경우를 다룹니다.

## 기울기

장면: `0.05 x 0.05 x 2.4` µm 셀이며, x·y는 주기 경계이고 z는 열린 경계입니다. 여기에
`ε = 2.25`인 `SnappedSlab` 막과 `PlaneWave` 가우시안 펄스(0.8 µm, `σ_f = 4e13` Hz)를
둡니다. 격자는 0.025 µm이고 800 단계를 실행합니다. 손실은 `TimeSeriesMonitor`,
`FieldMonitor`, `FluxMonitor`, 최종 장을 모두 더한 값입니다. 막의 유전율과 광원 진폭에 대해
미분합니다.

| 블록 `K` | 800 단계에서의 스케줄 | JAX | Torch CPU |
| --- | --- | --- | --- |
| 1 | 한 단계짜리 구간 800개 | ≤ 1e-12 | ≤ 1e-12 |
| 7 | 나머지까지 중첩된 세 단계 (343, 49, 7) | ≤ 1e-12 | ≤ 1e-12 |
| 30 | 한 단계, 구간 26개와 나머지 20 단계 | ≤ 1e-12 | ≤ 1e-12 |
| 1000 | 실행보다 김: 일반 스캔 | ≤ 1e-12 | ≤ 1e-12 |

각 항목은 손실과 두 미분값을 일반 스캔과 `rtol = 1e-12`, `atol = 0`으로 비교합니다. 개발 중
관측한 최대 상대 차이는 7e-16이었습니다. `K = 7`에서 손실은 NumPy 순방향 실행과 `1e-12`
이내로 일치합니다. 유전율 미분은 중심 차분(간격 `2.25e-5`)과 `1e-6` 이내로 일치합니다.
손실의 모든 항이 진폭의 제곱에 비례하므로, 진폭 미분은 `2 L / a`와 `1e-12` 이내로
일치합니다.

2차 미분은 Torch CPU에서 확인했습니다. 균질한 Lorentz·Drude 매질에 대한 기존의 정확한 헤시안
시험(17 단계, 닫힌 식 기준값, `2e-12`)에 `K = 3`인 CPU 사례를 추가했습니다. 이 사례는 9 단계
중첩 구간과 6·2 단계 나머지를 사용하며, 최종 장 손실과 기록 손실 모두를 확인합니다.

범위가 지정된 추적 물체도 확인했습니다. `Sphere` 반지름을 미분 입력으로 두고
(`Numerics(geometry_ranges=...)`, 120 단계, 즉시 실행 `torch.autograd`와 `jax.grad`), `K = 7`과
`K = 1000`은 일반 스캔의 손실을 정확히 재현하고 반지름 미분을 `1e-12` 이내(관측 `1.3e-15`)로
재현합니다. 일반 스캔의 미분은 NumPy 중심 차분(간격 `1e-4`)과 `1e-4` 이내(관측 `6e-7`)로
일치합니다. 추적 기하 사전 점검은 준비된 계획을 구체 장면에서 다시 만든 계획과 비교하는데,
체크포인트 블록은 계획 골격(skeleton)의 일부이므로 다시 만든 계획은 블록을 준비된 계획에서
가져옵니다. 그 밖의 차이는 여전히 거부합니다(`tests/fdtd/test_ranged_shape_checkpoint_grad.py`).

## 메모리

두 실행 길이 128 단계와 1,024 단계(8배)를, `K = 8`과 체크포인트 없음으로 비교합니다. 장면은
같은 막이며, JAX는 `0.5 x 0.5` 셀(10 x 10 x 48 칸), Torch는 `1 x 1` 셀(20 x 20 x 48 칸)을
씁니다. 둘 다 0.05 µm, `σ_f = 2e13` Hz입니다. JAX는 jit으로 컴파일한 기울기 전체에 대한
XLA 임시 버퍼 할당량(`compiled.memory_analysis()`)으로 잽니다. 이는 컴파일된 프로그램의
성질입니다. Torch는 새 프로세스에서 같은 prepared 계획으로 순방향을 한 번 실행한 뒤, 기울기
한 번을 계산하는 동안 프로세스 최대 상주 메모리가 얼마나 늘었는지로 잽니다.

Linux의 프로세스 최대값(`ru_maxrss`)은 프로세스 전체 기간의 값입니다. 그래서 기울기가
import나 첫 순방향 실행보다 작으면 증가가 전혀 없는 것으로 읽힙니다. CI 실행기에서 실제로
그랬습니다. glibc는 해제한 힙 페이지를 상주 메모리에 남겨 두고 다시 씁니다. 그래서 Linux
측정은 기울기 바로 직전에 최대값을 초기화합니다(`/proc/self/clear_refs`에 `5`를 쓰면 `VmHWM`이
초기화됩니다). 그 전에 `malloc_trim`을 호출하고, `MALLOC_MMAP_THRESHOLD_=65536`으로 큰 텐서가
재사용되지 않고 매핑·해제되게 합니다. 증가량은 `VmHWM`에서 초기화 시점의 상주 크기를 뺀
값입니다. 증가량이 0이면 측정이 아무것도 보지 못한 것이므로 시험이 실패합니다. WSL2 Ubuntu,
Torch 2.13 CPU에서 비율은 `K = 8`일 때 1.24, 체크포인트 없이 6.91이었습니다. 아래 표는
Windows 측정입니다.

| 백엔드 | `checkpoint_steps` | 128 단계 | 1,024 단계 | 비율 |
| --- | --- | --- | --- | --- |
| JAX (XLA 임시 버퍼) | 8 | 6.5 MB | 9.8 MB | 1.50 |
| JAX (XLA 임시 버퍼) | None | 22.1 MB | 169.8 MB | 7.69 |
| Torch CPU (최대 RSS 증가) | 8 | 69.0 MB | 98.2 MB | 1.42 |
| Torch CPU (최대 RSS 증가) | None | 119.2 MB | 917.9 MB | 7.70 |

체크포인트를 쓰면 단계 수가 8배 늘어도 스케줄 단계가 하나 늘 뿐이라 메모리는 약 1.5배입니다.
시험은 체크포인트 비율이 2 미만이고 일반 비율이 4 이상이기를 요구합니다. 두 번째 조건은
대조군이며, 이 측정이 실패할 수도 있음을 보여 줍니다.

## 변이 시험

각 변이는 제품 코드에만 적용했고, 표에 적은 시험을 그 변이에 대해 실행했습니다.

| 변이 | 잡아낸 시험 |
| --- | --- |
| 한 단계 스케줄 (항상 `unit = K`) | 두 메모리 시험 |
| `jax.checkpoint` 없는 JAX 구간 | JAX 메모리 시험 |
| Torch `Segment`를 중첩 `torch.utils.checkpoint`로 교체 | Torch 메모리 시험 |
| 고차 재계산을 저장된 입력 자체에서 시작 | CPU `cpu-k3-nested` 헤시안 |
| 매개변수를 `Segment` 입력으로 넘기지 않음 | Torch 기울기 일치 시험 |
| Torch 나머지 구간을 한 단계 일찍 시작 | Torch 기울기 일치 시험 |
| JAX 나머지 구간을 한 단계 일찍 시작 | JAX 기울기 일치 시험 |
| 단계가 제자리에서 쓰기 전에 구간 입력을 복사하지 않음 | Torch 기울기 일치 시험, 헤시안 |
| `numerics.checkpoint_scope`에서 JAX·Torch CPU를 다시 거부 | 중심 차분 시험 |
| 매개변수 없이 체크포인트된 Torch 스캔 실행 | 거부 시험 |

## 한계

- 메모리 상한이 아니라 메모리와 계산의 교환입니다. 스케줄 단계가 하나 늘 때마다 보관 상태가
  약 `K`개, 순방향 계산이 한 번 늘어납니다.
- 관측·광원 이력은 모든 보관 상태에 포함됩니다. 따라서 `TimeSeriesMonitor`나 `Record`는
  보관 상태마다 자기 이력을 한 번씩 더합니다. 이 상한은 장·흡수층·재료 기억에 적용됩니다.
- NumPy는 역방향 모드가 없어 거부합니다. `DecayStop`도 거부합니다.
- JAX 런타임은 장치에 무관하지만, 공개 API는 JAX를 CPU에서만 허용합니다. JAX GPU는 여기서
  측정하지 않았습니다.
- Torch CUDA 경로도 같은 `Segment`를 씁니다. CUDA 시험(체크포인트 블록 1, 3, 7, 11, 64와
  헤시안)은 CUDA 장치가 필요해 이번 기록에서 다시 실행하지 않았습니다. 위의 CPU 대응 시험은
  통과합니다.
- 주기 적층 솔버(`wavebit.fdtd.periodic`)는 자체 한 단계 블록 스케줄을 유지하며, 여기서
  바꾸지 않았습니다.
