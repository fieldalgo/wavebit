# 공개 전체 셀 형상 정책 보고

공개 클래스 `fdtd.SnappedSlab`과 `fdtd.SnappedBox`(이 기록을 남길 당시에는 `fdtd.Slab`과 `fdtd.Region`)는
내부 기하 클래스의 전체 셀 채우기 의미를 그대로 유지합니다. 공개 API의 낮추기(lowering)는 이들의 래퍼 타입을
보존합니다. 따라서 정확히 내부 클래스만 비교하면, 채우기 연산자가 바뀌지 않았는데도 이 내장 형상들이
`custom_shape_protocol`로 잘못 분류되었습니다. 기존의 Slab/Region/Sphere 혼합 보고 회귀 테스트가 이 문제를
`whole_cell_fill` 대 `custom_shape_protocol` 단언 실패로 드러냈습니다.

이제 분류기는 정확한 내부 Slab/Region 클래스와 정확한 공개 Slab/Region 클래스를 모두 인식합니다. 모든 하위
클래스를 내장 형상으로 분류하지는 않도록 일부러 설계했습니다. 사용자 하위 클래스는 자기 형상 프로토콜을 직접
소유하며 채우기 구현을 재정의할 수 있기 때문입니다. 스텐실 연산자와 접합 계획(junction plan) 분류는 바뀌지
않았습니다.

## 회귀 검사와 변이 검사

`tests/fdtd/test_policy_report.py`는 공개 Slab과 Region, 그리고 각각의 사용자 하위 클래스를 네 진입점,
즉 `check`, 준비 보고, `Prepared.validate`, `Prepared.run` 결과 출처(provenance)를 통해 검사합니다. 16개 사례
각각은 `rule=None`과 사유를 포함한 구조 정책 행 전체를 단언합니다.

macOS ARM64, Python 3.12.9, NumPy 2.5.1, JAX 0.11.0, Torch 2.14.1 환경에서:

- 수정 전에는 공개 클래스 사례 8개가 모두 사유 단언에서 실패했고, 사용자 하위 클래스 대조군 8개는 통과했습니다.
- 수정 후에는 16개 모두 통과했습니다. 정책 보고 파일 전체와, 관련된 준비 정책 승인 파일 및 공개 이산화 파일에서
  73개가 통과했습니다.
- 제품 분류기에서 두 공개 정확 타입을 제거하자 단언 실패가 8개 나왔으며, 공개 클래스 사례를 모두 포괄했습니다.
- 정확한 타입 소속 검사를 `isinstance` 검사로 바꾸자 단언 실패가 8개 나왔으며, 사용자 하위 클래스 사례를 모두
  포괄했습니다.
- 각 변이 후 제품 파일과 추적되는 다른 모든 파일의 바이트를 복원했고, 이어서 새 프로세스에서 16개 사례가 다시
  모두 통과했습니다.

이 검사들은 보고/출처 분류를 입증할 뿐, 필드 솔버 정확도에 대한 새로운 주장을 세우지는 않습니다. 추가된 생애주기
사례는 NumPy 백엔드를 사용하며, 관련 테스트 묶음은 기존의 백엔드 범위를 그대로 실행합니다. 교차 플랫폼 CI는 별도의
검사입니다. 골든 값이나 수치 허용 오차는 바꾸지 않았습니다.
