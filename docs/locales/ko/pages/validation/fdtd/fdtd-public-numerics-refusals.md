# 공개 수치 선택자 거부 메시지

공개 낮추기(lowering) 경로는 지원하지 않는 `Numerics.junction` 및
`Numerics.discretization` 값(이 기록 당시의 철자는 `discretisation`)을 거부합니다.
기존 공개 철자 회귀 테스트가 요구하듯이, 이 경로의 이른 거부 메시지는 여전히 공개 생성자와
선택자의 이름을 밝혀야 합니다.
이 수정은 어느 수용 조건식도, 어떤 필드 계산도 바꾸지 않고 그 맥락을 되살립니다. 구조화된
`invalid_input` 코드, 선택자 경로, 실제 값, 비어 있는 기대값, 오류 심각도는 그대로 유지됩니다.

## 근거

macOS ARM64, Python 3.12.9, NumPy 2.5.1, JAX 0.11.0, Torch 2.14.1에서:

- 기존 철자 테스트는 수정 전에 두 선택자 모두에서 실패했습니다.
- 추가한 여덟 사례는 `check`와 `prepare`, 각 선택자, 그리고 지원하지 않는 문자열 또는 `None`을
  다룹니다. 여덟 사례 모두 수정 전에는 메시지 단언에서 실패했고, 수정 후에는 구조화 필드 단언을
  포함해 모두 통과했습니다.
- 공개 철자, 공개 discretisation, 정책 보고서 파일 전체는 수정 후 109개 사례를 통과했습니다.
- 실제 제품 거부 각각에서 공개 맥락을 제거하자 변이마다 단언 실패가 네 개씩 나왔습니다. 두 변이를
  합치면 추가한 여덟 사례를 모두 다룹니다. 각 변이 뒤에는 추적되는 모든 파일을 바이트 단위로
  복원했고, 이어서 새 프로세스에서 여덟 사례가 모두 다시 통과했습니다.

이것들은 오류 보고 검사입니다. 추가적인 수치 정확도나 교차 플랫폼 실행 범위를 입증하지는
않습니다. 골든 데이터, 수치 임계값, 수용 조건, 건너뛰기 정책은 바꾸지 않았습니다.
