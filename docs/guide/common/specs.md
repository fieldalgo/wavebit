# Reproducible jobs

A `Job` records a solver name, immutable physical problem, numerics, and execution policy. It is an executable declaration rather than a dump of a mutable solver's last state.

```python
from wavebit import Job, Execution

job = Job(solver="rcwa", problem=problem, numerics=numerics,
          execution=Execution(backend="numpy", device="cpu", precision="double"))
encoded = job.to_json()
restored = Job.from_json(encoded)
assert restored.key == job.key
```

The [RCWA quickstart](../../getting-started/rcwa.md) contains a complete runnable example. `wavebit.run(job)` executes one Job with its own execution settings; a sweep is expanded into separate Jobs first. Serialization preserves supported physical declarations and units; unsupported values fail explicitly. Historical experiment records remain the original measurements and are not regenerated by converting a declaration.

`JobSpec`, mutable solver sweeps and the previous flat numerical vocabulary are documented in the [compatibility job manual](../../migration/jobs-v1.md). New code uses `Job` and solver-specific `Numerics`.

To preserve measured outputs as well as a declaration, use a [run record](../run-records.md).
It stores arrays, units, diagnostics and installed-source provenance alongside the Job.
Loading a record inspects saved data; rerunning its Job is a separate explicit operation.
