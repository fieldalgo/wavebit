# Docs

Public teaching, API contracts, theory, measured validation and design decisions. Start with
the [documentation home](index.md); the [section map](development/documentation.md) explains
where each kind of page belongs. Source comments cite the measured records below because
they explain numerical decisions and their limits.

**Which prose belongs here at all is decided by [`../CONTRIBUTING.md`](../CONTRIBUTING.md), and
that table wins over anything below.** What follows is the contract for a document once it is
here: what it must contain, and what it may point at.

House style: title, `Written:` date, a `Targets:` list of the files it explains, a TL;DR, then
tables. Say what was measured on what hardware, and where the result stops being trustworthy.
Every path in `Targets:` must resolve — `tests/api/test_docs_contract.py` checks it.

Live source citations use the current repository path, for example
`src/wavebit/rcwa/_engine/parametric.py`. Historical immutable records retain their
original bytes; exact source/document relocation ledgers resolve their old citations.
Those aliases do not excuse stale paths in current prose.

## A document here points inward only

`docs/` is published. Everyone who clones this repository gets it, so **a document may only
reference things that arrive with the clone**, plus the published literature:

| May cite | Must not cite |
| --- | --- |
| code, tests, studies and other docs in this repository | a path on anyone's machine — `/Users/...`, `~/project/...`, `/private/...`, `C:\...` |
| a DOI, an arXiv id, a public URL | a private study, an unpublished draft, an internal note |
| a released version of another project | a sibling checkout or scratch directory, however stable it feels |

Portable output destinations such as `artifacts/` are allowed when a command creates them.
State that these are local generated outputs, not evidence included in a fresh clone. Link
to committed measurements when making a published numerical claim.

The rule is not decoration; it is what this repository already got wrong. Four documents
pointed at directories that exist on one laptop, and the pointers named more than a location:
a private collaboration, an old project name, a folder of internal drafts. To a reader they
were dangling links, and to the author they were a disclosure nobody chose to make. The
committed git author field says *who* wrote this, which is attribution and belongs; a path says
*what else is on their disk*, which is neither.

**When the source really is outside, state the substance instead of the address.** A private
measurement is still evidence — write down what it measured and what the number was, and say
plainly that the raw record is not public. [branch cuts](theory/rcwa/branch-cuts.md) §7 is the pattern: it names the
golden that ships, dates the run it was cut from, and stops there.

One thing worth noticing about how the leaks were distributed: they were all in the documents
whose subject lives outside the code. A document explaining a solver implementation has no occasion to name a
directory. **If a draft here keeps wanting to point somewhere else, that is a signal it belongs
somewhere else** — private coordination rather than the maintained contributor guidance described in question 7 of the CONTRIBUTING table.

## Teaching pages and research records

The [getting-started pages](getting-started/index.md), [courses](learn/index.md),
[user guides](guide/index.md) and [API reference](reference/index.md) teach supported usage.
They do not require a measurement date or a `Targets:` list. The [theory](theory/index.md),
[validation](validation/index.md) and [design](design/index.md) sections distinguish derivations,
measured evidence and proposals. The research-record house style applies to those records,
not to every index or tutorial.

Imported historical learning records are a narrow, explicit exception to the outward-path
rule: their exact original bytes are retained with hashes in the
[import receipt](development/learning-provenance/import-receipt.json), and the repository layout
gate verifies those hashes. Those seventeen files are evidence rather than current navigation;
new prose links to their portable repository locations and does not repeat host paths.

Raw research notes, session transcripts, draft designs, private artifact links and
unreviewed notebook or prototype bundles stay in the separate private lab repository.
They are not published as downloads or copied into this repository's history.
Publish a maintained explanation only after reviewing its scientific claims, current
API, figures and licensing. Retain the source originals in the lab; preservation alone
does not make a source suitable for publication. The English guide and optional Korean
translations are the public reading routes.

## What a document here is not

- **Research records have a different role from the user manual.** The [guide](guide/index.md) teaches current usage; a validation record explains why a numerical decision was made and where its evidence stops.
- **A maintained explanation, not a running session log.** A document states current behavior,
  a measured result, or an explicitly dated design decision. Developer workflows and accepted
  implementation checkpoints belong here; private coordination and transient progress do not.
  Explain past defects where they justify current behavior or the interpretation of evidence.
- **Not a scratch pad.** An unfinished measurement lives in `studies/` until it decides
  something; scratch lives outside the checkout entirely.

## Docs vs tutorials

The site contains both introductory teaching and reference material. The [courses](learn/index.md)
and [getting-started pages](getting-started/index.md) teach concepts and first calculations;
[tutorial notebooks](../tutorials/README.md) provide executable explorations. Research records
remain citable Markdown with explicit conditions, recorded outputs and limitations.

## Languages and imported teaching material

English is the canonical route and default language. Forty complete imported course chapters
have English bodies and matching Korean source overlays; the homepage and five maintained guide
and developer pages also have full Korean overlays. Other pages use gettext where available and
otherwise show an explicit English-fallback notice. Both builds share document names and link to the same page in the other language.

The imported curriculum includes 100 figures, 15 runnable examples and seven drawing/measurement
tools. Original Korean assets and historical measurement records are retained with provenance.
English scientific plots change labels or use exact English originals; this migration does not
rerun solvers or claim additional physical convergence. Supplemental notebooks and research notes
remain individually inventoried review candidates rather than competing canonical chapters.
